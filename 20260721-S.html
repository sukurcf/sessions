II. What's New · Overview 04

Beyond code completion.

Copilot started as autocomplete. Today the same product plans work, edits many files, runs commands, and opens pull requests on its own. It moved from suggesting lines to completing whole tasks.

Autocomplete
Inline suggestions as you type. Accept with Tab.
→
Chat
Ask, explain, and fix in the IDE, on GitHub, and mobile.
→
Agent mode
Multi-file changes and tool runs, inside your editor.
→
Autonomous agents
Work in the cloud, terminal, and desktop app — open PRs.

V. Agents · Custom Agents 07

Build a custom agent.

# .github/agents/security-reviewer.agent.md --- name: security-reviewer description: Reviews diffs for security issues (OWASP Top 10) tools: ["read", "search"] model: Claude Opus 4.8 --- You are a senior security engineer. Review the diff and report each finding with a severity and a fix.
What it is

A reusable agent persona — instructions, allowed tools, and a model bundled into one file.

Where it lives

.github/agents/*.agent.md in the repo, or ~/.copilot/agents for personal use.

Frontmatter

name, description, tools, model, agents, handoffs. Omitting tools grants all tools.

Create it

Type /create-agent in agent mode and describe the persona. Manage with /agents.

Docs: code.visualstudio.com/docs/copilot/customization/custom-agents

VII. Terminal · Copilot CLI 09

Copilot in the terminal — key commands.

# Install (needs Node.js 22+) npm install -g @github/copilot # Start an interactive session copilot # Inside a session — add a file: > Fix the bug in @src/app.js # Cap AI credits for the session: /limits set max-ai-credits 50
Add context

@path/to/file pastes a file in; drag & drop or paste an image; /add-dir trusts another folder.

Track & compact

/context shows token usage; /usage shows credits, duration, lines; /compact compresses history.

Set a spend limit

/limits set max-ai-credits N caps a session; headless use --max-ai-credits N; /limits unset clears it.

Models & tools

/model switches model; /mcp add adds a server; /agent picks a custom agent.

? all commands Plan mode Shift+Tab /sandbox enable /resume /settings !cmd run shell
VIII. Terminal · Agent Skills 10

Agent skills.

# .github/skills/pdf-forms/SKILL.md --- name: pdf-forms description: Fill and validate PDF forms. Use when asked to edit or inspect a PDF document. --- Steps to fill a PDF form: 1. Load template via scripts/fill.py 2. Map fields from the input data 3. Validate output before saving
What it is

A folder of instructions and scripts Copilot loads only when the task is relevant.

Where it lives

.github/skills/<name>/SKILL.md in the repo, or ~/.copilot/skills.

Required fields

name and description — describe what it does and when to use it.

Use it

/skills list, /skills add; invoke a specific skill with /skill-name.

Instructions = always-on standards · Skills = load only when relevant

IX. MCP · Overview 11

Model Context Protocol.

MCP is an open standard that defines how an AI application connects to external systems. Copilot acts as a client and connects to MCP servers that expose tools, data, and prompts from your other tools.

Copilot
The MCP client — VS Code, CLI, or the app.
⇄
MCP server
Runs locally or remotely; one per tool.
→
Tools · Resources · Prompts
What each server makes available.
→
Your systems
Jira, databases, internal APIs, files.
Open standard — one server works across many AI tools Curated registry — github.com/mcp Enterprise policy is off by default

Source: modelcontextprotocol.io · docs.github.com/copilot

X. MCP · Configuration 12

Connect a server.

// .vscode/mcp.json { "servers": { "github": { "url": "https://api.githubcopilot.com/mcp/" }, "playwright": { "command": "npx", "args": ["@playwright/mcp@latest"] } } }
The key is "servers"

In .vscode/mcp.json (VS Code 1.99+). Some other clients use mcpServers instead.

Remote or local

Give a url for a hosted server, or a command + args to run one locally.

Turn it on

Click Start in the file, select agent mode, then open the tools picker.

Enterprise

"MCP servers in Copilot" is off by default — an admin enables it for Business/Enterprise.

Tip: don't configure the same server in both settings.json and mcp.json

XI. Practices · Playbook 13

Hackathon playbook.

01

Write specific prompts

A clear goal plus relevant context beats a vague ask every time.

02

Feed the right context

Use #file, #selection, and #codebase, or drag files into chat.

03

Set custom instructions

Put standards and build/test commands in .github/copilot-instructions.md.

04

Let auto pick the model

Reserve high reasoning and 1M context for hard, multi-file work — it costs more.

05

Review diffs, use checkpoints

Accept changes deliberately and roll back to a checkpoint when a path goes wrong.

06

Capture repeatable work

Turn flows you repeat into agent skills and custom agents your team can reuse.

XII. Practices · Pitfalls 14

Pitfalls & permissions.

Don't blanket-approve tools

--allow-all-tools and auto-approve give the agent the same shell access you have.

Launch from trusted dirs only

Never start the CLI in your home folder or a directory holding secrets.

Trust before pre-approving shell

Pre-approving shell in a skill removes the confirmation step — a prompt-injection risk.

Don't double-configure a server

Listing one MCP server in both settings.json and mcp.json can cause conflicts.

CLI approval model: allow once · allow for session · reject. Scope tools with --allow-tool='shell(git)'; --deny-tool wins. For headless or risky runs, use a sandbox: /sandbox enable or --cloud.
