03

Choose the right model

Use as much capability as the task requires, and as little as necessary.

What

Models differ in capability and cost. A reasoning model thinks deeply. A lighter model is fast and costs less.

Where

The model picker in Copilot Chat, or the /model command in Copilot CLI.

How
  • Reasoning model: architecture decisions, complex debugging, and system design.
  • Mid-tier model: the plan is clear, and you need efficient execution.
  • Lighter model: refactoring, formatting, and documentation updates.
Benefit

Routine work costs less. Quality can also improve: on some execution-heavy tasks, a reasoning model can overthink and make unnecessary changes.

04

Set the reasoning level

Match the thinking to the difficulty of the task.

What

Some models let you set how much the model thinks before it answers. A higher level uses more tokens and AI credits.

Where

VS Code and Copilot CLI, for models that support it.

How
  • Use the regular level by default.
  • Raise the level only for a hard task, for example a complex bug.
Benefit

Routine tasks use fewer tokens. Hard tasks still get deep thinking.

05

Let Copilot Fusion choose

Copilot Fusion picks one best model, or uses more models for review passes.

What

Copilot Fusion selects models for you. It uses capability signals for reasoning, code generation, debugging, and tool use.

Where

The model picker. Use Copilot Fusion as your default.

How

Select an effort level:

  • Fusion Standard: balances cost, quality, and speed.
  • Fusion High: balanced work with moderate token savings.
  • Fusion Max: top capability, with care for token use.
Benefit

Good model choices with no manual work. A reviewer gets only the context that it needs. Paid plans get a 30% discount on model costs with Fusion through 30 November 2026.

06

Use subagents on lighter models

A small, focused task often needs only a lighter model.

What

A subagent is a helper agent that does one part of a task. It has its own session. It does not inherit the conversation history.

Where

Agent sessions where the main agent gives a side task to a subagent.

How
  • Give each subagent one focused task.
  • Run each subagent on a cheaper model.
Benefit

Side tasks cost less. The main prompt cache stays warm, because a subagent does not switch the main model.

07

Write a complete prompt

A few extra words now can save many runs later.

What

A complete prompt has three parts: a clear task, the relevant context, and a stopping condition.

Where

Every prompt that you give to Copilot.

How
  • Task: say what to change, where, and the expected result. Do not write only “fix this issue”.
  • Context: give the files, services, logs, errors, and inputs at the start.
  • Stopping condition: say what “done” looks like.
Benefit

Fewer runs, with almost no extra tokens. Without a stopping condition, you can get extra commits, unrelated refactors, and scope growth.

08

Keep the context small

Open tabs, attached files, and long conversation history all count.

What

Copilot sends context with each request. More context means more tokens on each request.

Where

Copilot CLI and Copilot Chat.

How
  • Start a new conversation for an unrelated task: /new or /clear in the CLI, or a new chat session.
  • In Copilot CLI, use /compact to summarize a long session, for example /compact focus on the auth module.
  • In Copilot CLI, use /context to see what uses the context.
Benefit

Each request carries fewer tokens. The model sees the information that matters.

09

Map the project and trim tools

Give the agent a map. Enable only the tools that you need.

What

A project map tells the agent where things are. Each enabled tool adds its definition to the context on every request.

Where

Map: AGENTS.md or .github/copilot-instructions.md. Tools: your MCP server settings, for example the GitHub MCP server.

How
  • In the map, tell the agent where the main parts of the code are.
  • Enable only the toolsets that you need: --toolsets repos,issues or GITHUB_TOOLSETS="repos,issues".
Benefit

The agent goes directly to the right files. Each request carries fewer tool definitions.

10

Keep the prompt cache warm

Do not break the cache in the middle of a session.

What

Each turn sends the system prompt, file contents, and tool definitions again. The prompt cache stores these tokens.

Where

Every session with more than one turn.

How
  • Pick one model, or use auto model selection, and keep it for the session.
  • Set the reasoning effort, context size, and tools before you start.
  • After a long break, start a new session, or use /compact in Copilot CLI.
Benefit

Cached input tokens are typically billed at 10% of the normal input price. Later turns cost less.

11

Set a session limit

Cap the AI credits that one session can use.

What

An AI credit session limit caps the work that Copilot does in one session. It is a soft limit: a response in progress can finish above it.

Where

Copilot CLI and Copilot SDK (public preview).

How
  • Set it before the task starts: /limits set max-ai-credits 300
  • Remove it: /limits unset
  • In a script, the run ends at the limit: copilot -p "YOUR PROMPT" --max-ai-credits 300
  • To tune a task, find the lowest limit that still gives a good result.
Benefit

You avoid unexpected costs from one task. In a session, you choose to continue or raise the limit.

12

Split work into phases

Plan with a strong model. Implement with a cheaper model.

What

Divide a large task into three phases: research, plan, and implement.

Where

Large tasks in Copilot CLI or in Copilot Chat in VS Code.

How
  • Research: explore the code, and find the relevant files and dependencies.
  • Plan with a strong reasoning model. In the CLI, use /plan. In VS Code, select Plan in the agent dropdown, or type plan.
  • Implement against the plan with a cheaper model and a focused context.
  • Start a new session between phases.
Benefit

You do not carry unnecessary context forward. Each phase uses a model that suits it.

13

Learn from your sessions

Turn a one-time insight into standing guidance.

What

/chronicle makes useful insights from your session history.

Where

Copilot CLI, and the copilot-instructions.md file in your repository.

How
  • /chronicle tips finds ways to use Copilot more efficiently.
  • /chronicle cost-tips shows your token usage patterns and ways to reduce cost.
  • When it finds a recurring pattern, write it in copilot-instructions.md.
Benefit

You fix a recurring problem one time. You do not have to repeat the guidance.

14

Keep instructions short and useful

The instructions file is in the context on every run.

What

Good instructions are short and specific. They come from agent behavior that you saw, not from generic best practices.

Where

copilot-instructions.md in your repository. Personal and organization instructions can layer on top.

How
  • Write a rule for each pitfall that the agent repeats.
  • Remove one-off preferences and rare details.
  • Update the file when your code, architecture, standards, or workflows change.
Benefit

Even small improvements help on every run. You get fewer repeated errors and fewer wasted tokens.

15

Add guardrails

Give the agent a clear pass or fail signal.

What

Deterministic checks test each change from the agent. You need them because agents are not always correct.

Where

Multi-step agent work, where small errors can quickly compound.

How
  • Unit tests: check that the change gives the expected behavior.
  • Linters: keep structure and style consistent.
  • Security scans: find risky patterns early.
Benefit

Fewer retries, faster completion, and more predictable output. Total tokens are often lower, even if each step uses a few more.

Track usage and spending

See where your AI credits go. Then adjust.

What

The AI usage page shows your AI credit use for each feature and each model.

Where

The AI usage page, under github.com/settings/billing.

How
  • Find the features and models that use the most credits.
  • Set budget controls.
  • If you are often near your monthly limit, compare a higher plan.
Benefit

You adjust based on real data. A higher plan can cost less than paying for additional usage.
