I. Basics · Large language models 04

Large Language Models.

A model reads your text as tokens and predicts the next token, repeatedly. That single step is how every response is produced.

1Your promptInstructions, files, and your question — as tokens
2Predict next tokenThe model scores the most likely next token
3Append & repeatAdd the token, feed it back, predict again
4ResponseBuilt one token at a time until it stops

Example: you type // sort users by signup date and the model predicts the function body one token at a time. It has no access to your code or the internet unless you put that in the prompt.

I. Basics · How LLMs differ from normal software 05

Not like normal software.

Traditional programs follow rules a developer wrote by hand. A language model was never told the rules — it learned patterns from examples, so it behaves very differently.

AspectTraditional programLanguage model
Built byA developer writes explicit logic (if / else)Trained on huge text & code; learns patterns
Same inputAlways the same output (deterministic)Can differ each run (probabilistic)
CorrectnessExact and verifiablePlausible — can be confidently wrong
New situationsOnly handles cases that were codedGeneralizes to inputs it never saw
Fixing itEdit the code and redeployChange the prompt, or retrain the model

Example: a tax function returns the same number every time; ask Copilot for that function twice and you may get two different but valid versions — which is why you always review AI output.

I. Basics · How a model is built and served 06

How a model is built & served.

You usually don't run these models on your laptop. A provider trains one once, hosts it, and your tool reaches it over the network.

1Pre-trainRead huge amounts of public text & code; learn to predict the next token
2AlignFine-tune with human feedback so it follows instructions & stays safe
3ServeThe provider hosts the model behind an API endpoint
4UseCopilot & Claude Code send your prompt to that API and stream back tokens

Example: when you press Enter in Copilot Chat, your prompt travels to a provider's servers (such as Anthropic or OpenAI), the model runs there, and the reply streams back — you only ever use the finished model.

I. Basics · Tokens 08

Tokens.

A token is a small piece of text — often part of a word. Models read and write in tokens, not letters or whole words.

The sentence below splits into 9 tokens:
Copilot writes a Python function for me.
≈4 characters per token ≈0.75 words per token 100 tokens ≈ 75 words Code & non-English use more tokens

Cost is billed per token and every limit is measured in tokens. Example: a 200-line source file is roughly 2,000–3,000 tokens, so attaching whole folders fills the budget fast.

I. Basics · Context windows 09

Context windows.

The context window is the maximum number of tokens a model can consider in one request. Everything counts against this one limit — including the output.

Systemprompt
Instructionsyour rules
Toolsschemas
Filesattachments
Historyprior turns
Messageyours
Outputgenerated
AS IT FILLS UP → ANSWERS GET WORSE
Lost in the middleDetails buried in a long context get overlooked
Forgets earlier rulesInstructions drift as newer text crowds them out
Slower & pricierMore tokens to read means higher latency and cost

Example: attach 12 files when only 2 matter and the model may edit the wrong one. Include only what is relevant — start a new chat for a new task.

I. Basics · Agents 11

Agents.

An agent is a model plus tools plus a loop. Plain chat is one prompt and one answer; an agent repeats until the task is done.

1GoalYou state the task
2DecideChoose the next action
3Run toolEdit a file, run a command
4Read resultCheck output and errors
Repeat steps 2–4 until the task is complete

Example: "the build is failing — find out why and fix it." The agent reads the error, edits a file, re-runs the build, and repeats until it passes.

II. Context & prompting · System prompt 13

System prompt.

The top-level instruction block that sets the assistant's role and rules. You do not replace it — you extend it.

Built-in system prompt

Set by the vendor (Copilot, Claude Code). Defines the assistant's role, safety rules, and how it uses tools. Not directly editable.

Your additions

Custom instructions and a custom agent's body extend it. Claude Code appends with --append-system-prompt (inline) or --append-system-prompt-file (from a file).

Example: a review-only agent whose body states it never edits files.

II. Context & prompting · Custom instructions 14

Custom instructions.

Markdown files with standing rules, added automatically so you never repeat them — always-on files apply to every request; path-specific files apply only when their glob matches. 

your-repo/
├── AGENTS.md                     always-on
├── CLAUDE.md                     Claude Code
├── .github/
│   ├── copilot-instructions.md   always-on
│   └── instructions/
│       └── *.instructions.md     applyTo glob
└── .claude/
    └── rules/*.md                path-scoped
Copilot · .github/instructions/python.instructions.md
---
applyTo: "src/**/*.py"
---
Use type hints on all functions.
Claude · .claude/rules/api.md
---
paths:
  - "src/api/**/*.ts"
---
Validate every endpoint input.

Precedence high → low: personal · path-specific (applyTo / paths) · repository-wide (copilot-instructions.md, AGENTS.md).

II. Context & prompting · Commands and prompt files 15

Commands & prompt files.

Reusable Markdown files that hold a task's steps and run on demand with /name — unlike always-on instructions, they run only when you call them.

Copilot · .github/prompts/security-review.prompt.md
---
description: Security review of a REST API
tools: ['codebase', 'search']
---
Review ${file} for OWASP Top 10 issues.
Report findings as a table with severity.
Claude · .claude/commands/fix-issue.md
---
description: Fix a GitHub issue
argument-hint: [issue-number]
allowed-tools: Bash(gh issue view:*)
---
Fix issue #$ARGUMENTS.
Context: !`gh issue view $ARGUMENTS`

Type /security-review or /fix-issue to run. Copilot fills ${input:x} / ${file}; Claude fills $ARGUMENTS and runs !`cmd`. This repo has a real remotion-permission-levels.prompt.md.

II. Context & prompting · Prompt engineering 16

Prompt engineering.

Vague
"Make this code better."
No goal, no constraints, no output format → unpredictable result.
Specific
"Refactor for readability. Keep the public signature. Add doc comments. Do not change behavior. Return only the diff."
Clear goal + constraints + output → reliable result.
TECHNIQUES — STRUCTURE THE PROMPT
Zero-shot
Ask directly, no examples.
Classify the sentiment of this review: "Shipping was slow."
Few-shot
Show a few input → output examples first.
"love it" → pos "it broke" → neg "it's fine" → ?
Chain-of-thought
Ask it to reason step by step first.
Work through it step by step, then give the answer.
Role + format
Set a persona and the output shape.
You are a security auditor. Return findings as JSON.

Claude tip: wrap distinct sections in XML tags like <context> and <task> so the model can tell them apart.

III. Agentic · Agent mode 17

Agent mode.

The autonomous mode: the model plans, runs tools, edits files across the project, and runs commands until the task is done. Pick the mode that matches the job.

III. Agentic · Permissions 18

Permissions.

Permission levels control when an agent may run a tool without asking. Higher levels act faster; lower levels are safer — both tools sit on the same spectrum.

SafeAutonomous
GITHUB COPILOT · agent mode
Default ApprovalsConfirm sensitive tools before they run
Bypass ApprovalsAuto-approve all tool calls
AutopilotAuto-approve, auto-answer questions, continue
CLAUDE CODE · permission modes (Shift+Tab to cycle)
PlanplanRead-only; proposes a plan, no edits
ManualdefaultAsks before edits & commands
Accept editsacceptEditsAuto-applies edits; asks for the rest
AutoautoRuns all with a safety classifier
BypassbypassPermissionsSkips every check — VMs only

Copilot Bypass / Autopilot and Claude bypassPermissions skip prompts even for destructive actions — use only in isolated, reversible environments. Claude Code also layers .claude/settings.json allow / deny rules (dontAsk = locked-down CI).

V. Cost · Token economics 24

Token economics.

You pay per token. Rates differ sharply — output is the expensive part, and repeated content billed from cache is cheap.

≈0.1× input
Input
baseline
Output
≈5× input

GitHub Copilot: usage-based AI Credits with a monthly allowance (older annual plans use premium requests). Code completions are not charged per request on paid plans. Verify current numbers in the billing docs.

V. Cost · Token optimization 25

Token optimization.

FOUNDATION · PRACTICES
Scope context#filePoint at the 2–3 files a task touches
Terse promptsDrop filler — 30–50% less input
Constrain output"Code only" — output is ≈5× input
Compact often/compactAfter each sub-task; new topic = new chat
Right-size effortLower reasoning for renames & simple edits
SURFACES · TOOLS
Pick the modeAsk · Edit · Agent — Agent costs 5–25×
Model on AutoOverride only when a task needs it
Scope instructionsapplyToGlobs cut per-call context 50–80%
Delegate readsHeavy file reads → a subagent's own context
CLI over MCPDisable MCP servers you don't use
OBSERVABILITY · USAGE
Track creditsWatch AI Credit spend in Settings
Set a baselineMeasure one task before and after
Catch loopsIntervene on runaway agents; don't retry
Prune context filesKeep only non-obvious "landmines"
Read the errors"Limit reached" = context too large

Output costs about 5× input and Agent mode costs 5–25× more than Ask — terser prompts, scoped context, and the right surface and model compound into large savings.
