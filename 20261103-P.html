GitHub Agentic Workflows

GitHub Agentic Workflows

Repository automation with an AI agent. Write the task in Markdown; gh aw compiles it into a GitHub Actions workflow.

1. Trigger

An issue, schedule, or manual run starts the task.

2. Execute

Actions runs the agent using your Markdown instructions.

3. Analyse

The agent reads issues or code with allowed tools.

4. Publish

A separate safe-output job applies permitted changes.

Use it for

Issue triage, daily activity reports, documentation checks, and draft reviews. Reduce repeated analysis.

Keep the boundaries

Limit tools and permissions. Review published results. Keep predictable builds and tests in standard Actions.

Workflow syntax

Example: read open issues and create one report issue.

.github/workflows/issue-report.md
---
on: workflow_dispatch
permissions:
  contents: read
  issues: read
tools:
  github:
    toolsets: [issues]
safe-outputs:
  create-issue:
    max: 1
---
# Issue report
Read open issues.
Group by label and list blockers.
Create one report issue
with links to the source issues.

Trigger

workflow_dispatch adds a manual run option in Actions.

Read access and tools

The agent can read issues. The issues toolset provides relevant GitHub tools.

Controlled output

create-issue permits one report. A separate job handles the write.

Plain-language task

The Markdown body states what to analyse and what to produce. Configure AI authentication separately.

Model Context Protocol

What MCP does

Model Context Protocol (MCP) is a standard way for an AI app to request data or actions from other software.

Example task: "Read this GitHub issue and tell me what information is missing."

Without a connected tool

You open the issue, copy its text, and paste it into the chat. The model cannot read a private issue from a link alone.

With GitHub MCP

The app can request the issue through a GitHub tool. It gets the data that your account is allowed to read.

You ask

"Read issue 42."

→

App gets data

Uses GitHub MCP.

→

You get an answer

Based on the issue.

Use MCP to work with issues, files, or business data from a chat. MCP connects software; it is not an AI model and does not give extra access rights.

A function the app can call.

How a request works

You ask: "Read issue 42 in OWNER/REPO. List the problem and missing details."

1. Find tools

The app asks the connected server for its tool list.

tools/list
2. Select a tool

The model selects issue-read and supplies the repository and issue number.

3. Get the data

The app checks policy and required approval, then calls the server.

tools/call
4. Give an answer

The server returns issue data. The model uses it to write the answer.

You write the task. The app manages the connection and tool messages. You review the answer.

Source data does not guarantee a correct answer. If a call fails, check sign-in and repository access. Do not treat a failed call as an empty issue.

Model Context Protocol

Connect GitHub MCP

In VS Code with Copilot, add the GitHub server. Start with read-only tools.

.vscode/mcp.json · VS Code format
{
  "servers": {
    "github": {
      "type": "http",
      "url":
        "https://api.githubcopilot.com/mcp/readonly"
    }
  }
}

1. Save the settings

Create .vscode/mcp.json in your workspace and paste this JSON. The URL is the server address.

2. Start and sign in

Use MCP: List Servers in the Command Palette. Select GitHub and start it. Review trust and sign in when asked.

3. Check the tools

Open Copilot Chat in agent mode. Open the tool picker and check that GitHub read tools are enabled.

/readonly provides no write tools. Keep tokens out of this file. Your account and organisation policy still control access. Other AI apps can use a different settings format.
