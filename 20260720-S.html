IV. Architecture 06

How a request gets processed.

Every completion, chat reply, or agent action follows the same pipeline — from gathering context to a safety-checked response.

1 · Context gathering

Pulls in open files, workspace search, custom instructions, memory, and connected MCP servers.

2 · Proxy & pre-model filters

The prompt and context are sent to Copilot's proxy service, which applies pre-model filters — responsible-AI and content-exclusion checks — before forwarding the request to the selected model.

3 · Model & agent loop

The model replies directly, or — in agent mode — proposes a tool call, reads the result, and iterates.

4 · Post-model filters & delivery

Back through the proxy, post-model filters — duplicate-code detection and safety checks — run before the reply lands as ghost text, chat, a diff, or a PR.

Your code is never stored or used to train models, on any plan · docs.github.com/en/copilot/about-github-copilot

V. Assistive · Inline 07

Inline suggestions.

Ghost text completions as you type — from single lines to full function bodies. Accept with Tab, accept word-by-word with ⌘→.

Ghost text

Dimmed code suggestions that appear at your cursor position. Works across all major languages.

Next Edit Suggestions (NES)

Predicts your next edit location and content. Arrow in the gutter guides you — press Tab to navigate and accept.

Context-aware

Looks at current file, open files, and project context to tailor suggestions to your codebase style.

VI. Agentic · IDE 08

Agent mode.

Copilot works autonomously in your IDE — determining which files to edit, proposing code changes and terminal commands, iterating until the task is complete.

Multi-file edits

Agent plans the approach, edits files across your project, runs commands, and self-corrects on errors.

Run anywhere

Run locally, in background, or in the cloud. Hand off between agent types — context carries over.

Plan agent

Break tasks into structured implementation plans before writing code. Hand off to an implementation agent.

Sessions view

Run multiple agent sessions in parallel. Monitor from the Sessions view — see status, switch, review changes.

All plans include agent mode · Available in VS Code, JetBrains IDEs

VII. Agentic · CLI 09

Copilot CLI.

Use Copilot directly in your terminal — interactively or as a one-shot prompt. It ships with the GitHub MCP server by default, understands your issues and PRs, and can open pull requests on your behalf.

# Launch an interactive session in your project folder
copilot

# Run one prompt non-interactively — e.g. in CI
copilot -p "Add input validation" \
  --allow-tool='shell(git)'

Modes

Ask/execute by default; press Shift+Tab for Plan mode, which drafts a structured plan before writing any code.

Cloud & local sandboxes

copilot --cloud starts an isolated, resumable cloud session; /sandbox enable restricts local file and network access — both in public preview.

All plans · Install: npm install -g @github/copilot · docs.github.com/en/copilot/concepts/agents/about-copilot-cli

VIII. Extensibility · MCP 10

MCP servers.

The Model Context Protocol is an open standard that connects Copilot to external tools, data, and services — the same way across every AI client.

Local servers

Run on your machine over stdio; only add servers from sources you trust.

Remote / hosted servers

Run externally, typically authenticated with one-click OAuth or a token.

Configuration

Add servers in .vscode/mcp.json, or install with one click from the Extensions view.

Example servers

GitHub, Playwright (browser automation), Fetch (web pages), and Memory.

Servers can also expose resources, prompts, and interactive MCP apps · modelcontextprotocol.io

IX. Extensibility · Agents 11

Custom agents & agent skills.

Two ways to specialize Copilot beyond the built-in experience.

Custom agents

Defined in .agent.md files. Frontmatter sets a description, an allowed toolset, a model, and handoffs — giving Copilot a restricted persona, like a security reviewer or a planner.

Agent skills

A SKILL.md folder bundles instructions, scripts, and resources for one task. Copilot reads the description first, and loads the full skill only when it's relevant.

Agents define who's working; skills add what they know how to do — either can call MCP servers too.

X. Customization 12

Customize for your workflow.

Four more ways to tailor Copilot's everyday behavior to your codebase — beyond agents and skills.

Custom instructions

Define project-wide coding conventions in .github/copilot-instructions.md so AI matches your style.

Prompt files

Reusable .prompt.md files — share prompt instructions with context across your team.

Copilot Memory

Copilot stores and uses repository-level context — cloud agent and code review reference it automatically.

Hooks

Execute custom commands at specific agent events for automation and policy enforcement.
