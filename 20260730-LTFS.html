II. Session 1A · Spec-driven development 05

Spec-driven development · Spec Kit.

# install the CLI, scaffold a project uv tool install specify-cli specify init my-app --ai copilot # then, inside Copilot Chat: /speckit.constitution # principles /speckit.specify # the WHAT /speckit.plan # the HOW / stack /speckit.tasks # small tasks /speckit.implement # build it
.specify/ specs/spec.md plan.md tasks.md memory/constitution
What

Open-source GitHub toolkit. The specification becomes an executable artifact that drives implementation, run through the specify CLI and slash commands.

Why it helps

Separates the stable what (spec) from the flexible how (plan), so agents build to intent instead of guessing — strongest for feature work in existing systems.

Problem it solves

Replaces "vibe coding," where a vague prompt forces the model to invent thousands of unstated requirements and you find the wrong guesses late.

Resource · github.com/github/spec-kit  ·  github.github.io/spec-kit

III. Session 1A · Debugging & root cause 06

Debugging & root-cause analysis.

# auto-configure + launch a debug run copilot-debug node app.js # in Chat (agent mode, ⌃⌘I): /fix #terminalSelection Run the tests, then fix the failures. # steer with context references #codebase #file #symbol #testFailure
.vscode/launch.json chat.tools.terminal.autoApprove agent.autoFix = true
What

Agent mode reads errors, runs terminal commands, edits across files, and iterates. Helpers: /fix, copilot-debug, and /startDebugging to generate launch.json.

Why it helps

Automates the run → observe → fix → re-run loop. Auto-fix (default on) diagnoses generated code; workspace search traces a bug across files.

Problem it solves

Turns manual, repetitive debugging into a guided loop — and finds root cause by exploring the codebase, not just patching the symptom.

Resource · code.visualstudio.com/docs/copilot/guides/debug-with-copilot

IV. Session 1A · Testing & validation 07

Testing & validation · Playwright MCP.

// .vscode/mcp.json { "servers": { "playwright": { "command": "npx", "args": ["@playwright/mcp@latest"] } } }
.vscode/mcp.json top key: servers @playwright/mcp
What

A Microsoft MCP server that gives agents real-browser control through Playwright's accessibility tree — structured snapshots, not screenshots or a vision model.

Why it helps

The agent opens pages, clicks, types, and reads page state to validate the UI actually works. Deterministic and token-lean; it can also generate and run test suites, then self-correct.

Problem it solves

Confirms behavior, not just that code compiles — closing the gap between "it builds" and "it works."

Resource · github.com/microsoft/playwright-mcp  ·  code.visualstudio.com/docs/copilot/customization/mcp-servers

V. Session 1A · Security & review 08

Security, review & verify before merge.

# request Copilot as a PR reviewer gh pr edit 123 --add-reviewer @copilot # or automate it via repo Rulesets: ☑ Automatically request Copilot review ☑ Review new pushes / draft PRs # plus GHAS gates on the PR: CodeQL · secret scanning · Autofix
.github/copilot-instructions.md *.instructions.md AGENTS.md
What

Copilot code review leaves inline comments and one-click suggested changes on a PR. Alongside it: CodeQL, secret scanning, and Dependabot with Autofix.

Why it helps

A fast first pass (usually under 30 seconds) catches bugs and security issues before a human looks — guided by your instruction files.

The guardrail

Copilot only leaves a Comment — never Approve or Block. It never counts as a required approval. Human review plus passing CI stays mandatory before merge.

Resource · docs.github.com/copilot/concepts/code-review

VII. Session 1A · Multi-agent patterns 10

Multi-agent patterns for the enterprise.

# .github/agents/feature-builder.agent.md --- name: Feature Builder tools: ['agent','edit','search','read'] agents: ['Planner','Implementer','Reviewer'] mcp-servers: ['jira','database'] --- # coordinator delegates to scoped workers # planners = read-only; implementer edits
.github/agents/*.agent.md .vscode/mcp.json
Why multi-agent

Context isolation (workers return only a summary), specialization + least privilege (scoped tools per role), and parallelism (independent reviewers at once).

Core patterns

Orchestrator + workers · plan-then-implement handoff · parallel multi-perspective review · TDD-restricted delegation.

APIs & integrations

MCP servers bridge agents to enterprise systems — Jira, databases, internal services — governed by the org MCP policy and least-privilege toolsets.

IX. Session 1B · Custom & sub-agents 13

Custom agents & sub-agents.

# .github/agents/planner.agent.md --- description: Read-only planning agent tools: ['search','read'] model: Claude Sonnet 4.5 user-invocable: false --- Analyze the request and produce a step-by-step implementation plan.
.github/agents/*.agent.md .claude/agents/*.md org: .github-private/agents
Custom agents

Reusable personas — planner, security reviewer, architect — each with its own description, tools, and model. (Renamed from custom chat modes; .chatmode.md → .agent.md.)

Sub-agents

The main agent delegates a subtask and gets back only a summary. Needs the agent tool plus an agents: allow-list. Keeps the main context clean and enables parallel work.

Why it helps

Least-privilege by design: give planners and reviewers read-only tools; reserve edits for implementers. Define once at org level for consistent standards.

X. Session 1B · Reasoning · grounding · governance 14

Reasoning, grounding & governance.

# .github/instructions/py.instructions.md --- description: Python conventions applyTo: '**/*.py' --- - Follow PEP 8; use type hints. - Write tests for new functions. # plan mode: think before acting Shift+Tab to cycle chat / plan modes
.github/copilot-instructions.md *.instructions.md (applyTo) AGENTS.md
Reasoning

Plan mode makes the agent analyze, ask questions, and produce a plan before writing code. Escalate reasoning level only for genuinely complex tasks.

Grounding

Custom instructions, #-references, and MCP feed real project context — so the agent works from facts instead of guessing, which reduces hallucination.

Governance

Org policies, content exclusion (settings/REST, not .copilotignore), premium-request budgets, audit logs — and human review of every diff before merge.

Best practice · small scoped tasks · tests as guardrails · verify outputs  ·  code.visualstudio.com/docs/copilot/customization/custom-instructions

XI. Session 1B · Copilot CLI & SDK 15

Copilot CLI & SDK.

# standalone agentic CLI (not gh copilot) npm install -g @github/copilot copilot -p "Summarize this week's commits" \ --allow-tool='shell(git)' # embed the same engine in your app npm install @github/copilot-sdk # App → SDK → (JSON-RPC) → CLI server
@github/copilot @github/copilot-sdk AGENTS.md
Copilot CLI

A terminal-native agent (copilot). Edits code, runs Git and shell commands, and acts on GitHub — issues and PRs — with plan mode and built-in GitHub MCP. Not the old gh copilot suggest/explain.

Copilot SDK

Embeds Copilot's agent engine — the same runtime as the CLI — into your own apps and services over JSON-RPC. Multi-language: Node, Python, Go, .NET, Rust, Java.

Why it helps

Build custom agents and internal dev tools — custom tools + MCP, hooks, and BYOK — without writing your own orchestration layer.

Resource · docs.github.com/copilot/concepts/agents/about-copilot-cli  ·  docs.github.com/copilot/how-tos/copilot-sdk

XII. Takeaways 16

Four things to carry home.

Spec first, not vibe

Give agents a clear spec, plan, and small tasks. Intent beats guesswork on anything non-trivial.

Ground everything

Instruction files, #-references, and MCP anchor the agent to your real code and standards.

Verify before merge

Agent output still needs human review plus passing CI and security checks. The agent proposes; you approve.

Least privilege, many agents

Scope tools per role, isolate context with sub-agents, and govern MCP centrally for the enterprise.
