Foundations.

How you talk to Copilot, feed it context, and shape it to your codebase.

I.Module 1 · Foundations05

Chat modes.

One Chat view, three built-in agents. Pick how much autonomy you want.

Agent

The default. Edits code, runs terminal commands, and iterates until the task is done.

Plan

Read-only. Researches and writes a reviewable plan, then hands off to Agent to build it.

Ask

Answers questions and suggests code — without touching your files.

Demo

Switch agents from the dropdown at the bottom of the Chat view (⌃⌘I). Start in Plan, review the plan, then hand it to Agent.

I.Module 1 · Foundations06

Interaction patterns.

Reach Copilot from wherever you're working — pick the lightest surface for the job.

Inline chat ⌘I

Edit or generate right in the file or terminal. Keep or Undo in place — no context switch.

Chat view ⌃⌘I

The main panel for multi-step agent work and longer conversations.

Quick Chat ⇧⌥⌘L

A throwaway question without opening the panel.

Agents window

Run and watch several agent sessions side by side.

Demo

I.Module 1 · Foundations07

Providing context.

Copilot already sees your active file and selection. Add anything else with #.

#codebase search the repo #file a specific file #selection highlighted code #changes the current diff #fetch a URL #problems errors #terminalSelection terminal output

Be specific

Narrow context beats dumping the whole repo — sharper answers and fewer tokens.

Drag it in

Drop files, folders, images, or the Problems panel straight into chat.

Demo

I.Module 1 · Foundations09

Prompt discipline.

Specific prompts win. Say the constraints and expected output — then save the good ones as / commands.

.github/prompts/security-review.prompt.md--- description: REST API security review model: Claude Sonnet 4.6 --- Review ${file} for authz gaps, injection, and hardcoded secrets. List findings by severity with a suggested fix.
Write it well

State language, constraints, and expected output. Add tests as success criteria. Never say "make it better".

Reuse it

Variables${input:name} · ${selection}

II.Module 2 · Agentic Patterns14

Agents vs. skills.

Both customize Copilot — but they answer different questions.

Custom agent — the "who"

A role with fixed tools and a model that you switch into. Persists for the session. Lives in *.agent.md.

Agent skill — the "how"

A procedure Copilot auto-loads when the task matches, bundling its own scripts. Lives in SKILL.md.

Rule of thumb

Need a persistent reviewer persona? Agent. Need a repeatable test routine any agent can call? Skill.

II.Module 2 · Agentic Patterns15

Watch running sessions in the GitHub sidebar; open the PR or logs anytime.

II.Module 2 · Agentic Patterns17

Instruction layering.

Stack rules by scope. The agent merges them all — personal beats repository beats org on conflicts.

Precedence

Personal › Repository › Organization. All apply; the higher layer wins ties.

II.Module 2 · Agentic Patterns19

Agent quality.

Great results come from how you set up the task — not from a longer prompt.

Scope it tight

One clear goal, acceptance criteria, and which files to touch. Treat an issue like a prompt.

Give it a way to check

Point at tests or expected output so it self-verifies — the highest-leverage move.

Plan before code

For anything non-trivial: get a plan, review it, then implement.

Review the diff

Read edge cases and secrets, run tests, rewind a checkpoint if it drifts.

Demo

"Add a token-bucket rate limiter. Write tests: 10 req/s pass, reject the 11th, refill after 1s — then run them."

II.Module 2 · Agentic Patterns20

Token optimization.

Keep the context window lean to cut cost, latency, and drift.

New chat per task ⌘N

Don't make the model re-read unrelated history every turn.

Compact long sessions

/compact focus on … trims the transcript; auto-compaction kicks in near full.

Exclude the noise

search.exclude build output — grep matches cost tokens even when a file is never opened.

Right-size the model

Cheap model for grunt work; plan first so you don't pay for thrown-away code.

Demo

Context bar at 80% → /compact → the window shrinks so the next turns stay fast and cheap.

II.Module 2 · Agentic Patterns21

Iteration loops.

Steer as it runs and rewind when it drifts — never start over.

Steer mid-run

Send a follow-up while it's working to redirect — don't wait for a bad answer to finish.

Rewind, don't repair

Restore a checkpoint to a known-good state instead of chasing cascading errors.

Edit & re-run

Editing a past request reverts everything after it, then resends.

Demo

A 4-file change goes wrong on file 3 → Restore Checkpoint → add a constraint → resend. (Checkpoints undo file edits, not Git.)

III.Module 3 · Advanced Topics24

Custom MCP server.

Use the Python MCP SDK with FastMCP to expose safe actions, prompt templates, and readable data to Copilot.

server.py · pip install "mcp[cli]"from pathlib import Path from mcp.server.fastmcp import FastMCP mcp = FastMCP("team-context") @mcp.tool() def repo_policy(topic: str) -> str: return f"{topic}: write tests before merge." @mcp.prompt() def review_prompt(file: str) -> str: return f"Review {file} for risk and tests." @mcp.resource("repo://standards") def standards() -> str: return Path("STANDARDS.md").read_text() if __name__ == "__main__": mcp.run()
Primitives

Tools are callable actions. Prompts are reusable templates. Resources are URI-addressable data the client can read into context.

III.Module 3 · Advanced Topics25

Copilot memory.

Instructions tell Copilot how to behave; memory recalls durable facts you would otherwise repeat.

Instructions

Authored policy: .github/copilot-instructions.md, *.instructions.md, and AGENTS.md. Use for rules, style, tests, and team conventions.

Memory files

Learned recall: /memories/, /memories/repo/, and /memories/session/. Use for preferences, repo discoveries, and current task state.

The split

Instructions are source-controlled guidance. Memory is personal or local context that can be updated as the agent learns.

Keep it verifiable

Store short facts, commands, and conventions. Remove memories that become wrong or stale.

Example

"Always validate API input with Zod" belongs in instructions; "this repo calls services repositories" belongs in memory.

III.Module 3 · Advanced Topics26

Debugging & diagnostics.

When the agent behaves strangely, inspect the request path instead of guessing.

Logs

Chronological LLM requests, tool calls, context discovery, errors, durations, and token usage. Enable github.copilot.chat.agentDebugLog.enabled.

Flow Chart

Visualize parent agents, subagents, tool calls, retries, failures, and handoffs so you can see where the chain changed direction.

Cache Explorer

Compare cache hit/miss percentages, prompt signatures, request paths, and the divergence point between similar turns.

Context window

Inspect selected files, prompt payloads, model choice, tokens in/out, and remaining context window budget.

Chat Debug View

Review raw prompts, tool payloads, response metadata, and feature-flagged diagnostic views when available.

/troubleshoot

Ask why instructions, skills, or tools did not load, and correlate the answer with the debug logs.

Demo

Cache miss spike? Check the prompt signature and volatile context before blaming the model.

III.Module 3 · Advanced Topics27

Agent architecture patterns.

Design agent work like a small system: execution order, focused roles, visibility, and clean handoffs.

Sequential

Use when each step depends on the last: investigate → implement → validate → review.

Parallel

Use for independent work: one agent researches APIs, one audits tests, one reviews security.

Coordinator

The main agent owns the goal and delegates narrow tasks to subagents with isolated context and limited tools.

Multiagent

Compose planner, builder, reviewer, and domain specialists. Keep nesting shallow to control tokens and latency.

View execution

Use Logs and Flow Chart to inspect starts, stops, retries, tool calls, failures, and subagent summaries.

Handoffs

Return objective, files touched, validation run, unresolved risks, and the next recommended action.

Demo

Run research and test-audit subagents in parallel, then hand both summaries to one implementer.

III.Module 3 · Advanced Topics28

Off-ramp design.

Decide where autonomy stops: approvals control tool use, and Copilot / agent lifecycle hooks enforce policy at key moments.

copilot / agent lifecycle hooksSessionStart # load policy + memory UserPromptSubmit # classify risk PreToolUse # allow / deny / ask PostToolUse # log + verify result Notification # CLI only: route attention Stop # write handoff notes SubagentStop # summarize worker run PreCompact # preserve state
Approval levels

Default asks according to rules. Bypass auto-approves tools. Autopilot auto-approves, auto-answers, and keeps going when failure is cheap.

Guardrails
Danger zoneswrite/delete commands, secrets, prod paths, network calls
Client noteNotification is CLI-only; VS Code users rely on approvals and logs
Policy pointPreToolUse blocks or escalates before damage happens
Demo

Default for shared repos. Bypass in disposable worktrees. Autopilot only when rollback is easy.
