Foundations.

How you talk to Copilot, feed it context, and shape it to your codebase.

I.Module 1 · Foundations05

Chat modes.

One Chat view, three built-in agents. Pick how much autonomy you want.

Agent

The default. Edits code, runs terminal commands, and iterates until the task is done.

Plan

Read-only. Researches and writes a reviewable plan, then hands off to Agent to build it.

Ask

Answers questions and suggests code — without touching your files.

Demo

Switch agents from the dropdown at the bottom of the Chat view (⌃⌘I). Start in Plan, review the plan, then hand it to Agent.

I.Module 1 · Foundations06

Interaction patterns.

Reach Copilot from wherever you're working — pick the lightest surface for the job.

Inline chat ⌘I

Edit or generate right in the file or terminal. Keep or Undo in place — no context switch.

Chat view ⌃⌘I

The main panel for multi-step agent work and longer conversations.

Quick Chat ⇧⌥⌘L

A throwaway question without opening the panel.

Agents window

Run and watch several agent sessions side by side.

Demo

Select a function, press ⌘I, "wrap the fetch in try/catch and return a typed error" — it rewrites in place.

I.Module 1 · Foundations07

Providing context.

Copilot already sees your active file and selection. Add anything else with #.

Be specific

Narrow context beats dumping the whole repo — sharper answers and fewer tokens.

Drag it in

Drop files, folders, images, or the Problems panel straight into chat.

I.Module 1 · Foundations09

Prompt discipline.

Specific prompts win. Say the constraints and expected output — then save the good ones as / commands.

.github/prompts/security-review.prompt.md--- description: REST API security review model: Claude Sonnet 4.6 --- Review ${file} for authz gaps, injection, and hardcoded secrets. List findings by severity with a suggested fix.
Write it well

State language, constraints, and expected output. Add tests as success criteria. Never say "make it better".

Reuse it

Variables${input:name} · ${selection}

II.Module 2 · Agentic Patterns14

Agents vs. skills.

Both customize Copilot — but they answer different questions.

Custom agent — the "who"

A role with fixed tools and a model that you switch into. Persists for the session. Lives in *.agent.md.

Agent skill — the "how"

A procedure Copilot auto-loads when the task matches, bundling its own scripts. Lives in SKILL.md.

Rule of thumb

Need a persistent reviewer persona? Agent. Need a repeatable test routine any agent can call? Skill.

II.Module 2 · Agentic Patterns17

Instruction layering.

Precedence

Personal › Repository › Organization. All apply; the higher layer wins ties.

II.Module 2 · Agentic Patterns19

Agent quality.

Great results come from how you set up the task — not from a longer prompt.

Scope it tight

One clear goal, acceptance criteria, and which files to touch. Treat an issue like a prompt.

Give it a way to check

Point at tests or expected output so it self-verifies — the highest-leverage move.

Plan before code

For anything non-trivial: get a plan, review it, then implement.

Review the diff

Read edge cases and secrets, run tests, rewind a checkpoint if it drifts.

Demo

"Add a token-bucket rate limiter. Write tests: 10 req/s pass, reject the 11th, refill after 1s — then run them."

II.Module 2 · Agentic Patterns20

Token optimization.

Keep the context window lean to cut cost, latency, and drift.

New chat per task ⌘N

Don't make the model re-read unrelated history every turn.

Compact long sessions

/compact focus on … trims the transcript; auto-compaction kicks in near full.

Exclude the noise

search.exclude build output — grep matches cost tokens even when a file is never opened.

Right-size the model

Cheap model for grunt work; plan first so you don't pay for thrown-away code.

Demo

Context bar at 80% → /compact → the window shrinks so the next turns stay fast and cheap.

II.Module 2 · Agentic Patterns21

Iteration loops.

Steer as it runs and rewind when it drifts — never start over.

Steer mid-run

Send a follow-up while it's working to redirect — don't wait for a bad answer to finish.

Rewind, don't repair

Restore a checkpoint to a known-good state instead of chasing cascading errors.

Edit & re-run

Editing a past request reverts everything after it, then resends.

Demo

A 4-file change goes wrong on file 3 → Restore Checkpoint → add a constraint → resend. (Checkpoints undo file edits, not Git.)

III.Module 3 · Advanced Topics25

Copilot Extensions.

GitHub Apps that add a chat participant across Copilot — now largely superseded by MCP.

What they did

Answer as a participant on github.com, VS Code, and Visual Studio, backed by your own service.

The catch

Built as a GitHub App — no in-repo config and no full VS Code API access.

Reach for MCP

For a new tool or data integration, an MCP server is simpler and portable across editors.

Rule of thumb

New integration? Build an MCP server, not a GitHub App extension.

III.Module 3 · Advanced Topics28

Agent architecture patterns.

Structure complex work like a team: a coordinator delegating to focused workers.

Subagents isolate context

A worker runs in a clean context and returns only its result — the coordinator stays focused.

One role, one agent

Read-only planner, edit-capable implementer, strict reviewer — each with its own tools and model.

Keep chains shallow

Deep agent chains multiply tokens and credits. Nesting is off by default.

Why

A research subagent can run 40 tool calls and hand back a 5-line summary — the coordinator never sees the noise. Nesting caps at depth 5.

Three levels

Default (asks per your rules) · Bypass (auto-approve tools) · Autopilot (auto-approve + auto-answer). Bypass and Autopilot override your deny rules.
