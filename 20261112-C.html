Agent workflow

Use agents to help with the work. Keep the final decision with the team.

  1. Define

    Write the goal, limits, and acceptance criteria.

  2. Build

    Assign a task to the coding agent.

  3. Review

    Run checks and request a Copilot review.

  4. Decide

    A person checks the result and merges it.

Coding agent

Copilot works on a task in the background and proposes a pull request.

Use it for

  • Repository changes with a clear scope.
  • Bug fixes, tests, docs, or small features.
  • Tasks you can delegate while you work.

What it does

  • Reads the issue and repository context.
  • Changes files and can run checks.
  • Opens a pull request for your review.

You own the requirements, review, and merge decision.

Assign a task

On GitHub.com, start with an issue in a repository where the cloud agent is enabled.

  1. Write

    Create an issue with a specific result and clear limits.

  2. Assign

    In Assignees, select Copilot and add any extra guidance.

  3. Follow

    Open the session log. Review the pull request and checks.

Availability depends on your plan, repository settings, and organization policy.

Task brief

A small, testable issue gives the agent a better starting point.

Include

  • The result you need.
  • Files or behavior in scope.
  • Acceptance criteria and checks.
  • Changes the agent must avoid.
Example issue
Goal: Add pagination to the orders API.

Use 20 items per page by default.
Keep existing response fields.
Add tests for empty and final pages.
Do not change the database schema.

Example only. Change the details to match your repository.

Code review agent

Copilot examines changes and reports possible problems or suggestions.

Where

Review pull requests on GitHub or changes in supported IDEs.

How

Request Copilot as a reviewer, or configure automatic review.

Why

Get another view of bugs, edge cases, and maintainability.

Copilot can miss defects or make incorrect suggestions. Verify each finding.

Pull request review

Use the review as input, not as the final decision.

  1. Request

    In the pull request, select Copilot under Reviewers.

  2. Read

    Check the comments and their severity.

  3. Verify

    Inspect the code and test each relevant claim.

  4. Act

    Apply, fix, or dismiss a suggestion. Re-request review when needed.

Review controls

Trigger
Request a review manually or set an automatic review rule.
Guidance
Add review guidance in .github/copilot-instructions.md.
Re-review
Request it again after changes, or configure review of new pushes.
Approval
Copilot comments by default. Approvals can be enabled by policy.

Use required checks and human review as your team policy requires.

Orchestration patterns

A coordinator directs work, collects results, and checks the outcome.

Sequence

Complete one step before the next. Use it when work has dependencies.

Parallel

Run independent tasks at the same time. Combine their results.

Review loop

Build, check, and correct. Set a clear stop condition.

Use one agent for a small task. Delegation adds coordination and usage cost.

Parallel work

Split only tasks that can proceed independently.

Coordinator

Defines scope and gives each worker the context it needs.

ResearchFind relevant code.
TestsIdentify test cases.
ReviewInspect risks.

Combine

Check the results, resolve conflicts, and report the outcome.

For parallel edits, use separate files or isolated workspaces to prevent conflicts.

Task boundaries

Give each worker enough information to complete one bounded task.

Give

  • Goal: the question or change.
  • Context: files, requirements, and decisions.
  • Limits: permitted tools and actions.

Request

  • Result: findings, files, or a change.
  • Evidence: file paths and checks.
  • Stop: when the result is complete or blocked.

Reusable prompts

Save repeatable guidance in the form that matches its purpose.

Instructions
Repository rules that apply automatically when supported.
Prompt file
A task you run by name in a VS Code Local session.
Skill
A reusable workflow, with optional scripts and resources.
Custom agent
A specialist role with its own instructions and tools.

Support and file locations can differ by Copilot surface and harness.

Prompt files

.github/prompts/test-plan.prompt.md
---
description: Make a test plan
agent: agent
---
Review the selected change.
List test cases and edge cases.
Do not change files.

Use

In a VS Code Local session, enter /test-plan and add the change to inspect.

Include the goal, context, limits, and expected result.

The Local harness is deprecated. Use skills for new Copilot-harness workflows.

Agent skills

A skill packages a repeatable workflow for supported Copilot surfaces.

.github/skills/test-plan/SKILL.md
---
name: test-plan
description: Plan tests for a change. Use when preparing tests.
---
Read the change and related tests.
List cases, edge cases, and gaps.
Do not change files.

Use

  • Describe what the skill does and when to use it.
  • Add scripts or examples when needed.
  • Invoke it by name or let Copilot select it when relevant.

Sub-agents

A main agent delegates a focused task to a worker with its own context.

Delegate

Ask a worker to research, test, or review a defined part of the task.

Return

The worker reports the result to the main agent.

Combine

The main agent checks the result and continues the work.

A sub-agent does not remove the need to verify its result.

Sub-agent brief

Make the delegated request self-contained.

Specify

  • One goal and the relevant files.
  • Allowed actions and tool limits.
  • The result, evidence, and stop condition.
Example request
Use a sub-agent to inspect the
pagination tests in this repository.

Do not change files.
Return missing cases and file paths.
Stop after the test review.

Sub-agent tools and follow-up behavior differ by harness.

Handoffs

A handoff moves a completed stage to another role with context and a next prompt.

VS Code Local agent file
---
description: Plan a change
handoffs:
  - label: Implement plan
    agent: agent
    prompt: Implement the plan.
    send: false
---
Plan the task. Do not edit files.

Review, then continue

Read the plan before you select the handoff button. With send: false, review the next prompt before sending it.

This handoff configuration is for VS Code Local, not Copilot cloud agent. Local is deprecated.

MCP integrations

Model Context Protocol (MCP) connects an agent to external tools and data.

Copilot

Receives the task and selects a tool.

→

MCP server

Offers tools with defined inputs.

→

Service

Returns issues, logs, or other data.

Example: read an issue and related logs to investigate a failure.

MCP setup

Configuration is specific to the Copilot surface you use.

GitHub repository

  • Open Settings → Copilot → MCP servers.
  • Add a server and allow only required tools.
  • Store keys as Agents secrets with the COPILOT_MCP_ prefix.

VS Code

  • Add a trusted server through the MCP controls.
  • Sign in if required.
  • Check its tools before use.

Cloud agent can use configured MCP tools without asking for each call.

MCP safety

Trust

Use a server you trust. Inspect the publisher and the tools it exposes.

Limit

Use least-privilege credentials and allow only the required tools.

Verify

Treat external content as untrusted. Check data and tool results.

For GitHub code review, MCP tools must declare readOnlyHint: true.

Custom agents

Define a reusable specialist role with instructions and a selected set of tools.

Use a custom agent when

  • A role has a repeatable responsibility.
  • It needs a specific result or tool set.
  • You want to share the role with a team.

Define and verify

  • Store a repository agent in .github/agents/.
  • Describe its role, limits, and expected output.
  • Test its tool use and result on a small task.

Custom agent example

.github/agents/reviewer.agent.md
---
name: Reviewer
description: Review changes without edits
tools: ['read', 'search']
---
Check the supplied code and tests.
Report actionable findings with paths.
Do not edit files or run commands.

Why this works

  • The role has one clear job.
  • The tool list is limited to reading and search.
  • The result includes evidence.

Check tool names and supported fields for the target harness.

Copilot SDK

Build an application that uses the Copilot agent runtime.

Your app

Provides the task and controls access.

→

SDK client

Creates sessions and receives events.

→

Runtime

Processes prompts and available tools.

SDKs are available for TypeScript, Python, Go, .NET, Java, and Rust.

Configure authentication or a supported provider key. Runtime setup varies by SDK.

SDK example

TypeScript · Install @github/copilot-sdk
import { CopilotClient } from "@github/copilot-sdk";

const client = new CopilotClient();
try {
  const session = await client.createSession({
    model: "auto",
    onPermissionRequest: () => ({ kind: "reject" })
  });
  const reply = await session.sendAndWait({
    prompt: "Explain this repository."
  });
  console.log(reply?.data.content);
} finally {
  await client.stop();
}

This example rejects permission requests. Define a suitable permission policy for your app.

Decision guide

Build a change
Use the coding agent for a bounded task.
Inspect a change
Use Copilot code review and human review.
Repeat a workflow
Use a skill or a supported prompt file.
Use a specialist
Define a custom agent or delegate to a sub-agent.
Connect a service
Use a trusted MCP server with limited tools.
Build an app
Use the Copilot SDK and define permission controls.
