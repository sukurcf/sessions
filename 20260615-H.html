III.Billing shift05

From requests to GitHub AI Credits.

Starting June 1, 2026, GitHub is moving Copilot from request-based billing to usage-based billing. Copilot usage is measured in GitHub AI Credits, where 1 AI credit equals $0.01 USD.

Base credits

Individual paid plans include monthly base credits. These match the subscription price and do not change month to month.

Flex allotment

Plans currently include extra monthly flex credits on top of base credits. Flex is variable and adapts as model pricing, new models, and efficiency change.

How they apply

Base credits are used first. If usage goes beyond base credits, flex is applied automatically at the same rates across IDE, GitHub.com, and Copilot CLI.

Team pooling and budgets

Business and Enterprise credits are pooled at the billing entity level. Budgets can track or limit additional usage by enterprise, org, cost center, or user.

Why it matters

Token hygiene becomes a cost and reliability practice. A long agent session over many files may be worth it for a production incident, but a quick question should not carry an entire repository worth of context.

Source: GitHub Docs · Usage-based billing for individuals, organizations, and enterprises

IV.Token accounting06

What counts as tokens?

In usage-based billing, an interaction consumes input tokens, output tokens, and cached tokens. Those tokens are priced by the model used and converted into AI credits.

Input

What is sent

Your prompt, chat history, selected code, attached files, instructions, tool schemas, retrieved context, terminal output, and tool results.

Output

What is generated

The model's answer, explanations, code edits, plans, summaries, commands, and intermediate response text.

Cached

What is reused

Context the model reuses or stores across the interaction so repeated context can be handled more efficiently.

Billed in AI credits

Copilot Chat, Copilot CLI, Copilot cloud agent, Copilot Spaces, Spark, and third-party coding agents.

Not billed in AI credits

Code completions and Next Edit Suggestions remain unlimited for paid plans according to GitHub's usage-based billing docs.

V.Billing math07

How the calculation works.

Example using GPT-5 mini rates from GitHub's usage-based pricing table: $0.25 input, $0.025 cached input, and $2.00 output per 1M tokens. 1 AI credit equals $0.01 USD.

Token typeExampleCost
Input tokens20,000 × $0.25 / 1M$0.0050
Cached tokens10,000 × $0.025 / 1M$0.00025
Output tokens3,000 × $2.00 / 1M$0.0060
Total$0.01125 / $0.011.125 credits

Formula

For each token type: tokens used × model rate per 1M tokens. Add the parts, then divide by $0.01 to convert USD into AI credits.

Optimization lesson

If the same prompt includes a huge log, open files, and repeated chat history, input tokens rise before the model writes a single line. Shrinking context directly lowers the credit draw.

Illustrative estimate only · Actual usage depends on selected model, context, caching, and product behavior.

VI.Foundation08

Know where tokens go.

Every request carries more than your typed prompt: system instructions, repo customizations, active files, selected code, tool definitions, terminal output, search results, diffs, and chat history all compete for context.

01

Intent

What you typed, including task scope and desired output.

02

Instructions

Persistent rules from repo, user, organization, and agent files.

03

Context

Files, symbols, search hits, screenshots, terminals, and attachments.

04

Tools

Available tool schemas and previous tool results.

05

Response

Generated answer, code edits, explanations, and validation summary.

VII.Strategy09

The best context is selected, not piled on.

Instead ofDo thisWhy it improves output
Paste long logsShare failing test name, stack top, and command runModel sees the failure signal without drowning in repeated frames
Ask broad repo questionsReference likely files, symbols, or a Graphify querySearch becomes targeted and cheaper
Repeat standards manuallyMove stable rules into instructionsEvery future task starts with the same baseline
Use one giant promptPlan, edit, validate, then iterateShort feedback loops keep the model grounded in actual results

Real-world use case

A team debugging flaky CI can paste a 3,000-line log, but the useful signal is usually one command, one failing test, and one stack trace. With compressed output, the agent spends its reasoning budget on the fix path instead of sorting through noise.

VIII.Prompt design10

Prompt for decisions, not just output.

A strong prompt gives the model the shape of success: role, target, constraints, examples, boundaries, and validation.

# High-signal prompt skeleton
Goal: fix checkout tax rounding
Scope: billing service only
Context: failing test + changed config
Constraints: no DB migration
Done when: tests pass + edge cases listed

Make success observable

Ask for code plus the exact validation path. Models produce better work when the finish line is concrete.

Give one good example

A small example of style, API shape, or expected output can replace paragraphs of abstract instruction.

Real-world use case

For a legacy migration, ask Copilot to convert one endpoint first, preserve behavior, run the existing contract tests, and summarize differences. That creates a reusable pattern for the next endpoints.

IX.Persistent context11

AGENTS.md tells agents how to work here.

Copilot can use one or more AGENTS.md files in a repository. The nearest file in the directory tree can guide local behavior for monorepos, apps, packages, or special workflows.

What to include

Repo purpose, common commands, validation order, ownership boundaries, generated files, safety rules, and known flaky steps.

Token optimization value

The agent does not rediscover setup and structure on every task. One concise file replaces repeated search, failed commands, and back-and-forth.

# AGENTS.md
Always run npm test -- --runInBand before finalizing billing changes.
Generated API clients live in src/generated/; do not edit them directly.
Prefer service tests over snapshot updates for behavior changes.
X.Custom instructions12

Use .instructions.md for path-specific rules.

Repository-wide instructions set the baseline. Files under .github/instructions/ can target specific paths with applyTo frontmatter.

---
applyTo: "**/*.tsx"
---

Use existing design tokens.
Prefer accessible native controls.
Add tests for user-visible states.

Best fit

Framework conventions, language style, migration rules, security standards, and review preferences that apply only to certain files.

Real-world use case

A platform team can enforce Terraform naming, Python lint rules, and React accessibility separately. Copilot receives only the relevant rule set for the file being edited.

XI.Reusable workflows13

.prompt.md files turn good prompts into team assets.

Prompt files are reusable workflows for tasks that happen often: reviewing a PR, preparing a release, scaffolding a component, writing tests, or summarizing migration impact.

Repeatable

Every developer invokes the same workflow instead of retyping a long prompt.

Auditable

The prompt lives in the repo, so it can be reviewed and improved like code.

Compact

Only task-specific variables need to be supplied at runtime.

Real-world use case

For release notes, a release-notes.prompt.md can tell Copilot exactly how to read commits, group changes, flag breaking changes, and produce the expected format. The model spends tokens on the actual release delta.

XII.Tools and automation14

Skills, hooks, and MCP reduce manual prompting.

Skills

Specialized playbooks

Package instructions, examples, and resources for domain tasks like PDF extraction, slide creation, test triage, or security review.

Hooks

Lifecycle automation

Run commands at key agent events: format after edits, block unsafe paths, or compress terminal output before it enters context.

MCP

Structured external access

Expose databases, APIs, issue trackers, search indexes, or internal tools through typed model-callable interfaces.

Real-world use case

A security team can create a review skill, attach an MCP server for vulnerability data, and use a hook to run secret scanning after edits. The agent gets the right workflow and tools without a long ad hoc prompt.

XIII.Tool · Graphify15

Graphify: query the map, not the whole repo.

Graphify turns code, docs, PDFs, images, SQL, and media into a queryable knowledge graph. It produces graph.html, GRAPH_REPORT.md, and graph.json, then agents can ask graph queries instead of repeatedly grepping raw files.

# Common workflow
graphify .
graphify query "what connects auth to billing?"
graphify path "UserService" "DatabasePool"
graphify hook install

Why it saves tokens

It replaces broad repo exploration with graph questions, god nodes, communities, confidence tags, and shortest paths.

Real-world use case

During a monolith decomposition, ask Graphify which modules touch payments, invoices, and notifications. Copilot can plan changes from relationships instead of reading hundreds of files.

Repo: github.com/safishamsi/graphify · Research note: code extraction is local via tree-sitter; docs and PDFs may use model-backed semantic extraction depending on mode.

XIV.Tool · RTK16

RTK: compact command output before it reaches the model.

RTK is a Rust CLI proxy that filters common developer commands. It uses smart filtering, grouping, truncation, and deduplication to reduce shell output by roughly 60-90% on many workflows.

rtk git status
rtk git diff
rtk test npm test
rtk err npm run build
rtk gain
rtk discover

Good targets

Git status, diffs, test runners, linting, TypeScript errors, Docker/Kubernetes output, logs, dependency lists, and cloud CLI responses.

Real-world use case

When an agent runs a failing build, RTK can return grouped errors instead of a long raw transcript. The agent sees the exact files and error classes it needs to fix.

XV.Tool · Caveman17

Caveman: reduce output tokens and memory weight.

Caveman is a skill/plugin that asks agents to respond with compressed, direct language. Its repo reports an average output reduction around 65%, with extra utilities for compressing memory files and short review comments.

Where it helps

Status updates, reviews, summaries, commit messages, memory files, and repetitive agent chatter where verbosity adds little value.

Where to be careful

Do not compress away nuance for architecture tradeoffs, stakeholder explanations, training material, or safety-sensitive decisions.

Real-world use case

A team using agents all day can keep final summaries short and structured. The chat stays readable, and recurring memory files become smaller without losing commands, paths, or URLs.

Repo: github.com/JuliusBrussee/caveman · Caveat: output compression does not reduce hidden reasoning tokens; it mainly saves visible response/context growth.

XVI.Built-in workflow18

Use VS Code's compress output option for noisy terminals.

When terminal or tool output is too large, compressing it before sending it back into chat helps Copilot preserve the error signal while shedding repetitive logs, progress bars, dependency noise, and unrelated warnings.

Best inputs

Build logs, test reports, package install failures, server traces, CLI diagnostics, and long command transcripts.

Best practice

Pair compressed output with the exact command, expected behavior, and what changed recently. Compression helps most when the agent knows the question.

Real-world use case

A frontend build might print 800 lines but fail because one CSS import is missing. Compressing the output gives Copilot the failing module, stack top, and package context without flooding the conversation.

XVII.Model routing19

Copilot Auto model: route by task complexity.

Auto model selection lets Copilot choose an appropriate model for the work instead of forcing every task through the same model. Use it when you want a balanced default across speed, cost, and reasoning depth.

Use Auto for

Mixed agent tasks, exploratory fixes, routine refactors, and work where the required reasoning depth is unclear.

Choose manually for

Strict latency needs, known heavy reasoning, specific model strengths, demos, or policy-controlled environments.

Token angle

The cheapest token is the one you do not need; the second cheapest is one sent to the right model for the job.

Real-world use case

Use Auto for a cloud-agent issue that may require reading, editing, and fixing CI. Pin a stronger reasoning model only when the task is clearly architectural or the first pass shows the problem is subtle.

XVIII.Operating pattern20

A repeatable context budget workflow.

01

Orient

Read instructions, Graphify report, or narrow docs before searching broadly.

02

Select

Attach only files, symbols, logs, screenshots, or terminal output needed for the next decision.

03

Act

Edit or answer from the smallest plausible hypothesis. Avoid collecting context for comfort.

04

Verify

Run focused tests and feed compressed failures back into the loop.

Real-world use case

For a bug in checkout, start with the nearest failing test and service file. Only expand to Graphify paths, logs, or database schema if the local hypothesis fails.

XIX.Examples21

Real-world examples across the SDLC.

New repo onboarding

Generate copilot-instructions.md, add AGENTS.md, and build a Graphify map. New agents stop rediscovering project shape every session.

Large migration

Use Graphify to identify connected modules, prompt files for migration steps, and path instructions for language-specific conventions.

CI failure repair

Use RTK or compressed output for logs, then ask Copilot to fix only the failing area and rerun the exact command.

Security review

Create a review skill with org standards, attach security scan output, and use hooks to run policy checks after edits.
