II.GHEC · Update 1 of 6 · Sep 25, 202603

Managed settings, validated.

Available now

An in-product validator for enterprise managed settings for GitHub Copilot flags errors that can stop your policies from being enforced.

# 1 · Open the validator Enterprise AI controls page "Copilot settings validation" # 2 · Fix each issue (file + JSON path) copilot/managed-settings.json copilot/team-mappings.json + team settings files it references # 3 · Commit to the default branch of .github-private # 4 · Reload the Agents page, re-check

Malformed JSON

Catches broken JSON in the managed settings files, one of the errors that can stop policies from being enforced.

Unsupported configurations

Flags configurations that aren’t supported, each with the affected file and JSON path.

Invalid team mappings

Checks team-mappings.json and the team settings files it references.

Confirm the fix

After you commit, reload the Agents page and review the validator results to confirm the configuration is valid.

Source: github.blog/changelog/2026-09-25-enterprise-managed-settings-in-product-validator/ · Sep 25, 2026

III.GHEC · Update 2 of 6 · Sep 21, 202604

Credential inventory exports.

Available now

Enterprise owners can export every credential that can access the enterprise: one view across members and apps, built for incident response.

# UI · enterprise settings Settings › Authentication Security › Credentials Export CSV (next to "Overview") # REST · asynchronous CSV export POST /enterprises/{enterprise}/credentials/exports GET …/credentials/exports/{export_id}

REST docs note

The earlier list endpoint, GET /enterprises/{enterprise}/credentials, closes down on Oct 2, 2026. Use the export endpoints.

Every credential

SSH keys, classic and fine-grained PATs, OAuth App tokens, and GitHub App user-to-server and installation tokens.

Rich metadata

Owners, scopes and permissions, creation, expiration and last-used dates, and target organizations or repositories.

Filter and correlate

Filter by user, app, credential type, or organization. Correlate with audit log activity to gauge risk exposure.

Who and where

Enterprise owners and members with View enterprise credentials. Available on GHEC now; coming to GHES.

IV.GHEC · Update 3 of 6 · Sep 16, 202605

Automated SSO authorization.

Available now

Enterprise admins can bulk-authorize existing classic PATs and SSH keys for up to 50 organizations in one request, through an enterprise-installed GitHub App.

# GitHub App with enterprise_credentials:write POST /enterprises/{enterprise}/credential-authorizations { "credential_type": "classic_pat", "credential_id": 12345678, "organizations": ["octo-org", "octo-enterprise-org"] } # ssh_key: pass the key fingerprint · max 50 orgs

Good fit

Service accounts and automation credentials. Call the API whenever a token rotates or new organizations are added.

The friction

Authorizing credentials one SSO-protected organization at a time is manual work and encourages long-lived tokens.

Opt in, then delegate

Enable the new enterprise setting so enterprise-installed GitHub Apps with enterprise_credentials:write can call the API.

No secrets passed

The credential is identified by its non-secret token ID or SSH key fingerprint, so no secrets reach the app.

Checked before granting

Verifies the orgs are in the enterprise, the owner belongs to each, and enterprise-level SSO is used. Skips active authorizations.

Source: github.blog/changelog/2026-09-16-automate-sso-authorization-for-classic-pats-and-ssh-keys/ · Sep 16, 2026

V.GHEC · Update 4 of 6 · Sep 1, 202606

Live migrations, now GA.

Generally available

Enterprise Live Migrations (ELM) moves repositories from GitHub Enterprise Server to GitHub Enterprise Cloud with data residency with near-zero downtime.

gh extension install github/gh-elm gh elm configure gh elm migration create \ --source-org ORG --source-repo REPO \ --target-org ORG --target-repo REPO gh elm migration start --migration-id $MIGRATION_ID gh elm migration status --migration-id $MIGRATION_ID gh elm migration cutover --migration-id $MIGRATION_ID

Supported GHES versions

3.17.18+ · 3.18.12+ · 3.19.9+ · 3.20.3+ · 3.21.3+ · 3.22.0+

Cutover in minutes

Data syncs continuously while developers keep working. Cutover only drains the remaining in-flight changes.

Built for monorepos

Deep history, heavy issue and pull request volume, constant activity. Progress tracking surfaces failures before cutover.

Pairs with GEI

Use GitHub Enterprise Importer where brief downtime is fine and ELM where it isn’t. Run both concurrently.

Scriptable CLI

gh elm manages the lifecycle through the GHES REST API, with readable or JSON output for automation.

Source: github.blog/changelog/2026-09-01-enterprise-live-migrations-from-ghes-to-ghe-com-generally-available/ · Sep 1, 2026

VI.GHEC · Update 5 of 6 · Aug 26, 202607

Billing data for GitHub Apps.

Available now

Enterprise owners can grant a GitHub App the enterprise billing permission, so billing automation no longer depends on one person’s token.

Before

Personal access token

Belonged to an enterprise owner or billing manager. Automation broke when that person changed roles or left.

Now

GitHub App installation token

Carries the enterprise billing permission, read or read and write, and calls the enterprise billing REST API.

Pick a level

Select the enterprise billing permission when you create or configure the app: read, or read and write.

Use the billing API

An installation access token with the permission can call the enterprise billing REST API endpoints.

Automate finance work

Pull usage into finance and BI systems, reconcile invoices, and manage budgets and cost centers.

More resilient

Higher rate limits than a personal access token, and no dependence on one person’s role.

Source: github.blog/changelog/2026-08-26-github-apps-can-now-access-enterprise-billing-data/ · Aug 26, 2026

Generally available

# Organization level Settings › Repository # Repository level Settings › Rules # Either level Export to CSV

Repository charts

Aggregate view

Rule-evaluation metrics across every repository, so governance and compliance teams can report at organization scale.

Find the bypasses

Filter your way in

Report and audit

VIII.GHAS · Update 1 of 5 · Sep 25, 202609

Autofix that remembers.

Public preview

For customers who have enabled GitHub Copilot Memory, agentic autofix now reads existing memories for context and stores the fix patterns it creates.

01

Security alert

You use agentic autofix to resolve it.

02

Review memories

It reads existing memories for context that can help resolve the alert.

03

Create the fix

It proposes a fix for the alert.

04

Store the pattern

The fix pattern is saved as a memory for future use.

Resolves more alerts

Stored fix patterns help agentic autofix resolve additional security alerts.

Teaches other features

GitHub Copilot code review and cloud agent learn secure development patterns unique to your repository.

Needs Memory

Applies to customers who have enabled GitHub Copilot Memory.

Public preview

Both agentic autofix and GitHub Copilot Memory are in public preview.

IX.GHAS · Update 2 of 5 · Sep 9, 202610

Block secrets at merge.

Public preview

A new repository ruleset rule stops a pull request from merging while it introduces open secret scanning alerts.

# Repository > Rulesets (repo, org, or enterprise) Require secret scanning alerts are resolved # REST API type require_secret_scanning_alert_resolution parameters secret_types # GraphQL REQUIRE_SECRET_SCANNING_ALERT_RESOLUTION

Default scope

Runs on open pull requests and blocks provider-pattern secrets. You can also block other categories, such as custom or generic patterns.

Two checks

A secret scan has completed for the head commit, and no alerts are open for secrets the pull request’s commits introduced.

Developers resolve

Without bypass permission, developers clear the block by resolving each alert.

Beyond push protection

Adds a pull request layer for cases push protection can’t or isn’t set to catch, like generic patterns with push protection off.

Availability

Public preview for customers with GitHub Secret Protection or GitHub Advanced Security.

Source: github.blog/changelog/2026-09-09-block-pull-requests-with-exposed-secrets-from-merging/ · Sep 9, 2026

XII.GHAS · Update 5 of 5 · Sep 15, 202613

Enforce GHAS configurations.

Available now

Enterprise admins can now stop both organization and repository administrators from overriding security settings defined at the enterprise level.

“Enforcement” optionRepository ownersOrganization owners
Don’t enforceCan overrideCan override
Enforce for repository ownersLockedCan override
Enforce for repository and organization ownersLockedLocked

Where to set it

In a security configuration, choose from the “Enforcement” dropdown menu.

What changed

Enforcement only stopped repository owners from changing settings. It can now stop organization owners too.

Consistent policy

Security and compliance teams can apply the same GitHub Advanced Security settings across every organization.

Strictest option

Enforcing for repository and organization owners stops both from overriding what the enterprise defines.
