Copilot modes

Choose the type of work first. Then choose the model and permissions.

Ask

Understand code or compare options.No code changes are needed.

Select Ask in chat."Where is the access token checked?"

Plan

Research a change and identify decisions.Review the plan before implementation.

Enter /plan and the task."Add pagination. Keep old clients working."

Agent

Build, fix, or test a change.Uses tools, edits files, and runs commands.

Select Agent and give the result you need."Fix the failure and run its tests."

Custom
agent

Reuse a focused role.For example: a read-only reviewer or a test writer.

Create an agent file. Select its name.Chat: Open Customizations > Agents.

Mode is not model. The mode sets the workflow. The model performs the reasoning. Permissions control allowed actions.

A reusable reviewer

YAML between --- lines sets the role. Markdown below it gives the instructions.

.github/agents/reviewer.agent.md
---
name: Reviewer
description: Review changes without edits
tools: ['read', 'search']
---
Find incorrect behavior and missing tests.
Report the file, line, impact, and fix.
Do not edit files.
name
Name in the agent picker.
description
Purpose and when to use the agent.
tools
Tools for this role. Names depend on the runtime.
model
Optional model ID or ordered list.

More fields: reasoning-effort, model-policy, skills, hooks, invocation controls. Check runtime support.

Instruction files

Save project rules once. Copilot adds the applicable rules to its context.

Whole repositoryShared Copilot guidance

copilot-instructions.md

.github/copilot-instructions.md

Use for shared build commands, architecture rules, and test requirements.

# Project rules

Use the existing API error type.
Keep database calls in src/data.
Run npm test after behavior changes.

Format: Plain Markdown. No YAML header is required.

Use: Repository guidance on supported surfaces, not a new agent.

Matching filesRules for a language or folder

*.instructions.md

.github/instructions/tests.instructions.md

Add rules for matching files. Keep shared rules in the main file.

---
name: API tests
applyTo: "tests/**/*.ts"
description: API test rules
---
Reuse the shared test fixtures.
Test invalid input and empty data.

Fields: applyTo: root-relative globs, separated by commas. Optional: name, description.

Local: description can also load rules by task. It does not restrict applyTo.

Directory scopeGuidance that multiple agents can read

AGENTS.md

AGENTS.md   or   src/payments/AGENTS.md

Share context across compatible agents. Use nested files for folder rules.

# Payment module

Keep money values in minor units.
Use the shared currency type.
Run payment tests after edits.

Format: Plain Markdown. No YAML header is required.

Copilot: Combines root and nested guidance. Local: Enable root AGENTS support and chat.useNestedAgentsMdFiles.

Example: editing tests/api/orders.test.ts

Repository rules + matching test rules
+ applicable AGENTS.md guidance

Keep rules consistent. Precedence differs by runtime. Instructions are not security controls or tests. They do not control inline suggestions.

Prompt files and agent skills

A prompt saves one request. A skill packages a reusable procedure and its resources.

Prompt file VS Code Local only

Run a saved task manually. Useful for an existing Local workflow with a repeatable output format.

.github/prompts/test-change.prompt.md
---
name: test-change
description: Add tests for a change
argument-hint: "[file or folder]"
agent: agent
tools: ['read', 'search', 'edit']
---
Read the supplied code and existing tests.
Add focused tests for the changed behavior.
Use the project's existing test framework.

Run: /test-change src/api in a Local chat, or use the file's play button.

Available header fields: name, description, argument-hint, agent, model, tools. All are optional.

For new work, use a skill. Prompt files do not run in the Copilot runtime. Convert them before the Local runtime is removed.

Agent skill VS Code / App / CLI

Load steps and files on demand. Run by name or task match.

.github/skills/test-change/SKILL.md
---
name: test-change
description: Add focused tests when code changes.
---
1. Read the change and existing tests.
2. Use [checks](references/checklist.md).
3. Add tests. Run them. Report the result.

1. Name + description
2. SKILL.md body
3. Resources: references, scripts

Required: name matches the folder. description states when to use the skill.

Optional: argument-hint, user-invocable, disable-model-invocation. VS Code: experimental context: fork.

Skill controls: user-invocable: false hides the slash command. disable-model-invocation: true stops automatic loading. A skill does not grant tool permissions.

Agent orchestration

Run dependent work in sequence. Run independent work in parallel. Give each agent a clear task and stop condition.

Sequential handoff VS Code Local

A handoff changes the active agent in the same conversation. You review one stage before starting the next.

Planner

Proposes a plan

→
You

Check and choose

→
Agent

Implements the plan

.github/agents/planner.agent.md
---
name: Planner
description: Plan a change without edits
tools: ['read', 'search']
handoffs:
  - label: Implement plan
    agent: agent
    prompt: Implement the agreed plan.
    send: false
---
Research the task. Return a plan and tests.

Trigger: Plan with Planner, then select Implement plan. send: false lets you edit the prompt; send: true submits it after selection.

Local runtime only. Optional handoff field: model.

Parallel subagents

The main agent gives each task a separate context, then combines the results.

Use two subagents in parallel.
One: find the API's error-handling pattern.
Two: find the relevant test fixtures.
Do not edit files. Return paths and findings.
Combine the results into an implementation plan.

Copilot runtime

Name the role or custom agent. Delegation uses task. In CLI, use /fleet <task> for parallel work.

Local runtime

Enable Run Subagent. In a coordinator agent, use:

tools: ['agent', 'read']
agents: ['Researcher',
         'Test analyst']

Hide from picker: user-invocable: false. Block delegation: disable-model-invocation: true. Local agents lists can override.

Subagents share files. Avoid concurrent edits; use isolated worktrees.

Code review

Find defects before merge. Local feedback and GitHub pull request reviews use different controls.

Choose the surface

VS Code

Select code > right-click > Review, or use Source Control > Review Changes for uncommitted changes.

GitHub Copilot app

Pull requests > Files changed > New session. Ask for a review, inspect comments, then submit from Review.

Copilot CLI

Run /review or /review src/api. It analyzes changes and returns feedback in the terminal.

GitHub.com

Open a PR > Reviewers > Copilot > Request. A ruleset can request reviews automatically.

Check each finding. Review severity is High, Medium, or Low. Effort is a separate setting. Copilot comments by default; approving reviews require explicit configuration.

Review environment

GitHub.com runs setup in GitHub Actions. This file does not configure local reviews.

.github/workflows/copilot-code-review.yml
on: workflow_dispatch
jobs:
  copilot-setup-steps:
    runs-on: ubuntu-latest
    permissions: { contents: read }
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v7
        with: { node-version: '22' }
      - run: npm ci

Required job ID: copilot-setup-steps. Job fields: runs-on, steps, permissions, services, snapshot, timeout-minutes (maximum 59).

Fallback: copilot-setup-steps.yml in the same folder. Commit the workflow to the default branch.

Review guidance: Use instruction files (slide 4). Set excludeAgent: "code-review" to exclude a path-specific instruction file.

GitHub.com effort

Lite

Fast, targeted feedback on clear issues.

Balanced

Deeper reasoning. The default level.

Max

Multiple high-reasoning models.

Adaptive

Chooses a level from risk and complexity. Public preview.

Choose under PR Reviewers. Administrators set defaults and maximums. Higher effort uses more AI credits.

Firewall

Settings > Copilot > Internet access > Copilot code review

Keep the firewall enabled. Select the recommended allowlist and add only required domains or URLs to the custom allowlist.

Organization rules and repository rules combine. These controls are separate from cloud-agent firewall settings.

Do not put firewall or effort fields in the setup YAML. Setup steps are outside the agent firewall's coverage. Keep their commands and dependencies trusted.

Canvases

Share a browser, document, spreadsheet, or custom panel. Use /create-canvas.

Repository configuration

Use the settings UI, or edit the repository file. Review and accept file-based configuration before it runs.

.github/github-app.yml
instructions: "Use existing test commands."
scripts:
  - name: Setup
    command: npm ci
    triggers: [session.create]
  - name: Run
    command: npm run dev
server_ready_pattern: '(http://localhost:\d+)'
auto_open_in_browser: true
automation:
  auto_issue_session: true
  remote_control: false

Scripts: name, command, optional triggers. Triggers are session.create and session.archive. No trigger means manual use.

Browser: The first regex capture supplies the server URL or port.

The automation block is not a schedule. Set the recurring task, environment, and trigger in Automations > Create automation.

Image: Paste a clipboard image with Ctrl+V or Alt+V, as supported by your terminal and OS. Check that the attachment appears before sending.

Spec-driven development

GitHub Spec Kit turns intent into a specification, a plan, tasks, code, and evidence.

Start with the behavior

Use Spec Kit for several related requirements. Define acceptance criteria and resolve gaps before coding.

Example: "Export orders to CSV. Include current filters. Return a header-only file when there are no orders."

Terminal setup — new project
uv tool install specify-cli
specify init order-export --integration copilot
cd order-export

Then open Copilot in this folder. Run the following skills in chat, not in the terminal.

Project principles

/speckit-constitution

Start with rules for validation, tests, and compatibility.

Before planning

/speckit-clarify

Resolve gaps in requirements before choosing an implementation.

After planning

/speckit-checklist

Check whether requirements are clear and complete. This is not a runtime test suite.

Before implementation

/speckit-analyze

Find conflicts in spec, plan, and tasks. Read-only; edit the source documents.

Files to maintain

Edit the feature's spec.md, plan.md, and tasks.md when requirements or decisions change.

Active feature

.specify/feature.json records the feature directory. A Git branch change alone does not select a feature.

Close the loop

Converge adds missing tasks. Implement them and check again. Review the result before you merge.

Current Copilot syntax: /speckit-* in default skills mode. Older prompt integrations and some other agents use /speckit.*. Check the integration you installed.

Universe 2026 highlights

Copilot Fusion

Choose Standard, High, or Max. Copilot selects one model or combines models for the task.

Copilot Projects

Give Copilot a goal. Coordinate context, sessions, and results across repositories.

Copilot Automations

Run reusable tasks on demand, on a schedule, or from triggers. Control actions and cost.

Copilot Connectors

Connect supported services once. Reuse managed MCP connections across Copilot surfaces.

Security canvas and AI Scan

Inspect code-scanning findings beside your work. Use AI Scan for repository and PR analysis.

AI secret detection

Detect unstructured secrets before a push. Enable push protection and AI detection.

Package firewall

Block risky npm packages before installation by developers, agents, or CI runners.

Dependabot reachability

See which vulnerable functions your JavaScript code calls. Use this evidence to prioritize fixes.

GitHub platform

Stacked pull requests: review linked changes in smaller units. Issue artifacts: keep plans and research with the issue. GitHub CLI --attach: add images and videos.

These are recap highlights, not an availability guarantee. Check each feature's documentation for plan, policy, platform, and preview requirements.
