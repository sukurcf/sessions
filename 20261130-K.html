03

Stacked PRs

Split a big change into small pull requests that build on each other.

WhatGA 6 Oct 2026

A stack is a chain of small pull requests. The bottom PR targets main. Each next PR targets the PR below it. Each PR shows only its own changes.

Why
  • Small PRs get reviews faster.
  • Rules and CI run on every layer.
  • Merge the top PR to land the whole stack.
  • Merge queue works with stacks.
How
  1. Install the gh-stack extension once.
  2. Run init, then add for each layer.
  3. Run submit. GitHub pushes the branches and opens linked PRs.
  4. Merge on the PR page, or run gh stack merge.
File

No config file. Your branch protection rules and rulesets apply to every layer.

github.comGitHub CLIGit 2.36+
Terminal
gh extension install github/gh-stack
gh stack init
gh stack add -Am "Add sign-in API"
gh stack submit
gh stack merge

Limits: No stacks across forks. GitHub Desktop does not support stacks. A middle PR cannot merge alone.

04

Issue artifacts

Keep plans, notes, and links on the issue. Each artifact keeps its versions.

WhatPublic preview

An artifact is a document that you attach to an issue. It can be a plan, a Markdown note, a link, or an HTML page.

Why
  • Plans stay with the issue, not in a chat.
  • People and agents read the same document.
  • Restore an older version with the gh CLI.
How
  1. Open an issue. Select Artifacts.
  2. Select +. Choose Add link, Create artifact, or Create HTML artifact.
  3. Or run gh issue artifact create.
  4. The Copilot app can attach its plans for you.
File

No file in the repository. Artifacts live on the issue. Use the page, the gh CLI, or the REST API.

github.comCopilot appGitHub CLI

generic

Markdown note

plan

Implementation plan

link

URL to outside work

embedded_html

Interactive HTML page

Terminal
gh issue artifact create 142 signin-plan.md
gh issue artifact list 142 --type link
gh issue artifact edit 142 2 --restore-version 5

REST: POST /repos/{owner}/{repo}/issues/{n}/artifacts

type
generic, plan, link, or embedded_html
name
Title in the artifact list
body
Markdown, HTML, or the URL

Careful: Deleting an artifact is permanent. These are not Actions artifacts. The gh artifact commands need version 2.103.0 or later.

05

Attach from the CLI

Add screenshots and videos to issues and pull requests from the terminal.

WhatGA 1 Sep 2026

The --attach flag uploads a local image or video. GitHub hosts the file and changes your local path to a link.

Why
  • No browser drag and drop.
  • Scripts and agents can add before and after screenshots.
  • A video on its own line shows a player.
How
  1. Add --attach ./file.png to the command.
  2. Write the file as a Markdown image: ![](./file.png).
  3. Add #text after the path for alt text.
  4. Repeat the flag for more files.
File

No config file. It is a flag on gh issue and gh pr: create, edit, and comment.

GitHub CLI 2.99.0+
Terminal
gh pr create --title "Fix login" \
  --body "Before: ![](./before.png)" \
  --attach ./before.png \
  --attach './login.png#Login page after fix'
Types
PNG, JPEG, GIF, WebP, SVG, MP4, MOV, WebM
Images
Up to 10 MB each
Video
10 MB on Free, 100 MB on paid plans
Count
Up to 50 files per command

Limits: Images and video only. You need push access. GitHub Enterprise Server is not supported.

PR inbox

One list of the pull requests that need you now.

WhatGA 9 Jul 2026

PR inbox is a page at github.com/pulls/inbox. It sorts your pull requests into groups. It shows what to do next.

Why
  • See your next action, not every open PR.
  • Save the filters that you use each day.
  • Move through the list with the keyboard.
How
  1. Open github.com/pulls/inbox. No opt-in is needed.
  2. Read the three groups.
  3. Type a filter. Select + to save it as a view.
  4. Press j and k to move.
File

No file. You change the filter in the search box.

github.com

(author:@me OR review-involves:@me) AND repo:OWNER/REPO

PRs that you review, or were asked to review

Combine filters in one view

Tip: Save one view for each repository that you work in.

Copilot Fusion

Pick how much effort you want. Copilot picks the models and the steps.

WhatGA 28 Oct 2026

Fusion is one choice in the model picker, not one model. For each prompt it picks the models and the steps. You get one answer.

Why
  • No manual model switching.
  • Easy tasks stay quick.
  • Hard tasks get a second look.
How
  1. Open the model picker. Select Copilot Fusion.
  2. Choose Standard, High, or Max.
  3. Admins: AI controls → Copilot → Models → Configure Copilot Fusion models.
File

managed-settings.json sets model and fusionTier. A fixed tier locks it. overridable lets users change it.

github.comAppCLIVS CodeJetBrains
Copilot CLI
copilot --model fusion \
  --fusion-tier high -p "Fix the test"
managed-settings.json
{ "model": "fusion",
  "fusionTier": { "overridable": "standard" } }

Billing: AI Credits. Paid plans get 30% off through 30 Nov 2026. Effort levels differ by plan.

Copilot Projects

Keep the work for one goal in one place in the Copilot app.

WhatPublic preview

A project groups the sessions, files, and schedules for one goal. It lives in the Copilot app.

Why
  • See all sessions for a goal together.
  • Find the sessions that need your input.
  • Keep project files in one Library.
  • Run repeat work on a schedule.
How
  1. In the sidebar, select + next to Projects.
  2. Add repositories if you want. Write the goal as a prompt.
  3. Track sessions on Overview.
  4. Use Library and Automations.
File

No config file. You manage a project in the app tabs.

Automations

Save a task once. Copilot runs it on a schedule or when an event happens.

What

An automation is a saved prompt. It starts on a schedule or on a GitHub event, such as a new issue.

Why
  • Repeat work runs without you.
  • Events start work at once.
  • You set AI-credit limits for each run, day, week, and month. A run limit is 30 credits or more.
How
  1. Open Agents → Automations in the repo. Or use the app tab.
  2. Write a name and a prompt.
  3. Choose a trigger, tools, and a model.
  4. Save. Or use the REST API.
File

No file in Git. Use the UI or the API. For code-defined workflows, see GitHub Agentic Workflows.

github.comAppVS Code
name, prompt
Required
type
personal or shared. Fixed after you create it
triggers
A schedule or GitHub events
tools, model
Optional. Also reasoning_effort
POST /agents/repos/OWNER/REPO/automations
{ "name": "Issue triage",
  "prompt": "Label each new issue",
  "triggers": { "issue_opened": { "query": "is:open" } } }

Limits: Private and internal repositories only. You need write access. Anyone with read access can read run logs. Keep secrets out of prompts.

Connectors

Sign in once. Use GitHub-verified tools in many Copilot surfaces.

WhatPublic preview

Connectors are hosted MCP servers for other tools, such as Slack, Linear, and Sentry. GitHub hosts and verifies them.

Why
  • No server to install or run.
  • One sign-in for many surfaces.
  • Admins choose which servers are allowed.
How
  1. App: Customize → MCP → GitHub verified → Connect.
  2. CLI: run /mcp, then Connectors.
  3. VS Code: Agents window → Customizations.
  4. Web: github.com/copilot/customize.
File

None for connectors. Your own MCP servers use .mcp.json or .github/mcp.json.

github.comAppCLIVS Code
Admin policies
Editor preview features and MCP servers in Copilot
Registry
Allow all. If you set allowedMcpServers, add the connector URL
managed-settings.json
"allowedMcpServers": [{ "serverUrl":
  "https://api.github.com/copilot-connectors/api/v1/connectors/*/mcp" }]

Limits: No support for sessions that run on GitHub Actions. A deny rule wins over an allow rule.

Security canvas

See security findings in a side panel. Ask Copilot to explain or fix them.

WhatPublic preview

A canvas in the Copilot app. It lists code-scanning findings and runs a security review of your local changes. It comes from the github-security plugin.

Why
  • Findings sit next to your code.
  • Copilot explains a finding or fixes it.
  • Local review needs no code scanning.
How
  1. Customize → search github-security → Install.
  2. In a session, select + → Canvas → Security.
  3. Open Code scanning findings. Or select Security review → Start review.
  4. Select findings. Choose Explain or Fix.
File

No config file. The plugin manifest is plugins/github-security/plugin.json.

Copilot app only
Code scanning findings
GitHub alerts, with a filter
Security review
Your local changes. Or run /security-review
Terminal
copilot plugin install github-security@awesome-copilot

Limits: The standalone CLI is not supported. No GitHub Enterprise Server. It shows code-scanning alerts only. A local fix does not close the GitHub alert.

AI Scan

AI finds security problems that code scanning can miss.

WhatPublic preview

AI Scan adds findings to code scanning. It scans a whole repository on demand. It also scans pull requests in languages that CodeQL does not cover.

Why
  • More languages are covered.
  • Findings are normal alerts.
  • Assign alerts to Copilot for a fix.
How
  1. Admin: allow the AI Scan policy. It is off by default.
  2. Repo: Security and quality → Code scanning → AI Scan → Standard scan.
  3. Open an alert. Assign it to Copilot. You can select up to 25.
File

No YAML file. The REST API uses repository_scan and pr_scan.

github.com

Repository scan

On demand. Default branch. All languages.

Pull request scan

PHP, Shell, Terraform, Dockerfile, and more.

Billing
Code Security AI credits
License
No Copilot license is needed
Run
By hand. There is no schedule

Limits: Findings are advice. They cannot block a merge. No scans on fork or Dependabot PRs.

AI push protection

Block a push when AI finds a secret that has no fixed pattern.

WhatPublic preview

Push protection checks each push for secrets. With AI, it also finds generic secrets, such as passwords. It is off by default.

Why
  • A secret never reaches the repository.
  • You do not need to rotate it later.
  • Developers see the problem at once.
How
  1. Open Settings → Security and quality → Advanced Security → Secret Protection.
  2. Turn on Push protection and Scan for AI-detected secrets.
  3. Turn on Push protection for AI-detected secrets.
File

No file. For many repositories, use a custom security configuration. Needs Secret Protection. It uses AI credits.

github.comgit push
secret_scanning_generic_secrets
enabled
secret_scanning_push_protection
enabled
secret_scanning_generic_secrets_push_protection
enabled
Fix the commit, then push again
git commit --amend --all
git push

Bypass: Open the URL in the error. Pick a reason. Push again within 3 hours.

14

Package firewall

Block risky npm packages before they reach your machine.

WhatPublic preview

A registry proxy for npm. It checks each package before npm install. It is for GitHub Enterprise Cloud.

Why
  • Malware is blocked early.
  • New and risky packages wait.
  • One rule set for the whole enterprise.
How
  1. Admin: enterprise Policies → Package firewall. Set the rules.
  2. Developers: point .npmrc to the firewall.
  3. If a package is blocked, npm prints a URL to ask for an exception.
File

.npmrc. Use your own user file. Do not commit the token.

npmEnterprise Cloud
.npmrc (ENT = your enterprise)
registry=https://package-firewall.githubapp.com/npm/enterprises/ENT
//package-firewall.githubapp.com/npm/enterprises/ENT/:_authToken=${GITHUB_TOKEN}
GITHUB_TOKEN
Token with access to your enterprise. Keep it out of Git
Minimum age
1 to 365 days. Use 0 to turn it off

Limits: npm only. Local caches can hide the firewall.

15

Dependabot reachability

Fix the alerts that your code can actually reach first.

WhatPublic preview

Reachability analysis checks if your code can call the weak part of a dependency. Each Dependabot alert gets a verdict. It is for JavaScript and TypeScript with a lockfile.

Why
  • Less noise from alerts.
  • You fix the risky alerts first.
  • Free in preview.
How
  1. Open Settings → Advanced Security.
  2. Turn on Dependabot alerts.
  3. Turn on Reachability analysis.
  4. Filter your alerts.
File

No dependabot.yml change.

github.comEnterprise Cloud
Dependabot alerts search box
reachability:reachable,potentially-reachable
Languages
JavaScript and TypeScript
Package managers
npm, pnpm, or Yarn. A lockfile is required
Runners
GitHub-hosted only

Limits: Reachable does not mean exploitable. GitHub rescans every 24 hours. A scan stops after 3 hours. Each alert shows up to 5 sample call paths.

Awesome Copilot

A community library of files that you can reuse with Copilot.

What

Awesome Copilot is an open collection of Copilot files. Browse it at awesome-copilot.github.com. The source is the github/awesome-copilot repository.

Why
  • Start from an example, not a blank page.
  • One site for each file type.
  • Open source. You can add your own.
How
  1. Pick a type on the site.
  2. Read the files.
  3. Copy the files into your repository. Or install the plugin.
File

Each type has its own path. See the list on the right.
