XV. Agent · Permissions 16

Permission levels.

Control how much autonomy the agent has during a session — from fully supervised to fully autonomous.

Default Approvals

Uses your configured approval settings. Tools that require approval show a confirmation dialog before they run. Agent may ask clarifying questions if needed.

Bypass Approvals

Auto-approves all tool calls without showing confirmation dialogs. Automatically retries on errors. Agent may still ask clarifying questions.

Autopilot (Preview)

Auto-approves all tools and auto-responds to clarifying questions. Continues working autonomously until task is completed. Continuous iteration & auto-retry.

Tool approval management

Chat: Manage Tool Approval — review & configure pre-approval (skip dialog) and post-approval (skip result review). Reset all: Chat: Reset Tool Confirmations.

Terminal & sandbox

Auto-approve commands: chat.tools.terminal.autoApprove. Sandbox: chat.agent.sandbox.enabled (off | on | allowNetwork). Restricts file system & network.

Quick toggle: /yolo · /autoApprove · /disableYolo · Default setting: chat.permissions.default

XVIII. Cloud · Setup steps 19

copilot-setup-steps.yml.

A GitHub Actions workflow that configures the cloud agent's VM before it starts coding — install deps, set up toolchains, configure runners.

# .github/workflows/copilot-setup-steps.yml
name: "Copilot Setup Steps"
on:
  workflow_dispatch:
  push:
    paths: [.github/workflows/copilot-setup-steps.yml]

jobs:
  copilot-setup-steps:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v4
        with: { node-version: "20", cache: "npm" }
      - run: npm ci

Location & format

.github/workflows/copilot-setup-steps.yml — full GitHub Actions workflow. Must have a job named copilot-setup-steps.

What you can customize

steps, permissions, runs-on, services, snapshot, timeout-minutes (max 59). Other job settings are ignored.

Runners

Default: ubuntu-latest. Upgrade to larger runners or self-hosted (ARC). Windows supported for Windows toolchains.

Validation

Auto-runs as a normal workflow on push to copilot-setup-steps.yml. Must be on default branch to take effect.

GitHub Actions syntax · Secrets & variables supported · Self-hosted runners · LFS: checkout with lfs: true

Custom instructions.

Define coding standards, conventions, and rules that automatically influence how AI generates code. No need to repeat them every prompt.

--- (YAML frontmatter)
name: 'Python Standards'
applyTo: '**/*.py'
---
# Python coding standards
- Follow PEP 8 style guide.
- Use type hints for all functions.
- Use dataclasses for data models.
- Prefer pathlib over os.path.

Always-on instructions

.github/copilot-instructions.md — auto-applied to every request
AGENTS.md — multi-agent compatible
CLAUDE.md — Claude Code compatibility

File-based instructions

*.instructions.md — applied based on applyTo glob pattern. Stored in .github/instructions/ or user profile.

User-level

~/.copilot/instructions/ — personal rules applied across all workspaces. Not version-controlled.

XXIV. Customization · Precedence 25

Instruction precedence.

Instructions cascade from most specific to least specific. Higher-priority instructions win on conflicts.

① Path-scoped (most specific)

.github/instructions/*.instructions.md with applyTo: globs — conditionally applied based on file path match

② Repository-level

.github/copilot-instructions.md — auto-applied to every chat request in this repo

③ Organization-level

Set by admins in org Copilot settings — shared across all repos in the org

④ Copilot defaults (least specific)

Built-in system behavior — base instructions when nothing custom is provided

How all instructions combine

All matching instructions are merged and sent to the model. Conflicts resolved by precedence order (most specific wins).

Monorepo support

Enable chat.useCustomizationsInParentRepositories to inherit instructions from parent repos in monorepo setups.

Generate with AI

/init for copilot-instructions.md
/create-instruction for targeted files
AI analyzes your codebase and generates rules.

Generate: /init for copilot-instructions.md · /create-instruction for targeted files · Monorepo: enable chat.useCustomizationsInParentRepositories

XXVII. Agent orchestration 28

Agent orchestration.

Compose complex workflows with subagents, handoffs, and forked context — each agent runs in its own context with specific tools and model.

Subagents

Agents can spawn subagents for specialized tasks. Define allowed subagents via agents property. Use * to allow all. Each subagent runs in its own context.

Handoffs

Sequential workflows: Plan → Implement → Review. Handoff buttons appear after response. Set send: true to auto-submit to next agent.

When to use

Complex tasks needing multiple expertise areas: plan + implement + review + test. Each agent focused on one concern.

Forked context

Skills with context: fork run in a dedicated subagent. Only the final result returns to parent — keeps main context clean.

Nested subagents

Enable chat.subagents.allowInvocationsFromSubagents for deep orchestration chains — subagents spawning subagents.

Use cases: code review pipelines, multi-language projects, security audit + fix chains, feature → test → docs workflows

XXVIII. Customization · Skills 29

Agent Skills.

Folders of instructions, scripts, and resources that Copilot loads when relevant. They solve the context window problem.

The problem: context window limits

Instructions are always loaded into the context window, consuming tokens even when irrelevant. With many instruction files, the context fills up fast — leaving less room for actual code and conversation.

The solution: on-demand skills

Skills are loaded only when relevant to the current task. Copilot reads the skill's description and decides whether to load it — keeping the context window clean for what matters.

SKILL.md format

YAML: name, description, user-invocable, context (inline/fork). Body: Markdown instructions.

Locations

.github/skills/, .agents/skills/, ~/.copilot/skills/. Each skill = directory with SKILL.md + scripts.

Invoke & discover

Type /skill-name in chat. Also auto-loaded by relevance. Community: github/awesome-copilot.

Instructions = always on · Skills = on-demand · Use skills for large domain-specific knowledge bundles

XLIII. Techniques · Prompting 43

Prompt engineering techniques.

Craft better prompts to get better results. These techniques work across Copilot Chat, Agent mode, and CLI.

Zero-Shot

Ask directly without providing examples. The model relies entirely on its training to respond.

"Write a function that validates an email address using regex."

Few-Shot

Provide 2–3 examples of the desired input → output pattern. The model learns the pattern and generalizes.

"Convert these: 'hello' → 'HELLO', 'world' → 'WORLD'. Now convert: 'copilot' → ?"

Role Prompting

Assign a persona or expertise to shape the response style, depth, and focus area.

"You are a senior security engineer. Review this authentication code for OWASP Top 10 vulnerabilities."

Chain of Thought (CoT)

Ask the model to reason step-by-step before answering. Improves accuracy on complex, multi-step problems.

"Analyze this function step by step: What does each line do? What edge cases exist? Then suggest improvements."

Meta Prompting

Ask the AI to generate or refine the prompt itself. Useful when you're unsure how to frame a complex request.

"What's the best way to prompt you to refactor this 500-line file into clean modules? Generate that prompt for me."

More techniques

Tree of Thought — explore multiple reasoning branches in parallel
ReAct — interleave reasoning + actions (agent mode does this)
Constrained output — specify format: JSON, table, bullet list
Self-consistency — ask multiple times, pick the majority answer
Iterative refinement — build on previous response with follow-ups

Tip: combine techniques — e.g. Role + CoT + Few-Shot for best results · Agent mode uses ReAct + CoT internally
