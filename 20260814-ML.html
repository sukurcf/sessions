II. Why this exists 04

The context-switching tax.

Directing several agents on real work usually means juggling a terminal, an IDE, a browser tab for issues and pull requests, and another tab for CI — one task per surface, with no shared state between them.

GitHub Copilot, broadly

94%

developer productivity increase reported by Grupo Boticário

One surface instead of four

The GitHub Copilot app gives you a single place to direct AI agents across parallel workstreams, triage issues and pull requests, and manage the full development lifecycle — without hopping between terminals, IDEs, and browser tabs.

III. Overview 05

What is the GitHub Copilot app.

A desktop application purpose-built for agent-driven development. It's built on GitHub Copilot CLI and integrates natively with GitHub, so your repositories, branches, and CI pipelines work out of the box.

One command center

Direct multiple AI agents across parallel workstreams from a single desktop surface.

Built on Copilot CLI

Shares session data, slash commands, and history — including /chronicle — with the CLI.

Native to GitHub

Repositories, branches, issues, pull requests, and CI checks work with no extra setup.

V. Overview · Setup 07

From download to first diff.

Four steps get you from a fresh install to a reviewed pull request.

1. Install & sign in

Download for your OS, then authenticate with GitHub (or GitHub Enterprise Server).

2. Connect a project

Add a local folder, a GitHub repository, or clone from any Git URL.

3. Start a session

Pick a mode, describe the task, and let the agent create a branch and propose changes.

4. Review & ship

Inspect the diff, iterate, then create a pull request without leaving the app.

VI. Core concept · Sessions 08

Every task gets its own workspace.

A session is an isolated agent workspace — its own git worktree and branch — so parallel tasks never collide.

New working tree

The default: a dedicated worktree and branch, isolated from whatever you're doing locally.

Local repository

Run the session directly against the repository already checked out on your machine.

Cloud sandbox preview

A fully isolated environment hosted by GitHub — keeps running even if your laptop doesn't.

Active sessions are grouped by repository in the sidebar — click any to switch. Quick chats give you a conversation mode with no branch or worktree at all, for scoping before you commit to a session.

Source: docs.github.com/en/copilot/how-tos/github-copilot-app/agent-sessions · Aug 2026

VII. Core concept · Autonomy 09

Set how much initiative the agent takes.

Change the mode at any time, mid-session, as a task moves from exploration to execution.

INTERACTIVE

You and the agent, together

The agent suggests changes and waits for your input before proceeding to the next step.

PLAN

Approve the approach first

The agent researches the repository and drafts a plan. You review and approve it before any code changes.

AUTOPILOT

Fully autonomous

The agent writes code, runs tests, and iterates end-to-end without waiting on you at each step.

Source: docs.github.com/en/copilot/how-tos/github-copilot-app/agent-sessions · Aug 2026

VIII. Core concept · Models 10

Pick the model, or let Auto decide.

Every session lets you choose a model and reasoning effort — and change either one mid-session.

Auto model selection

The app picks the optimal model for the task's complexity, then shows which model answered each turn.

Bring your own model

Configure your own provider (BYOK) and those models appear in the same picker as GitHub-hosted ones.

Reasoning effort

Raise it for hard problems that deserve more thinking time; lower it for routine, well-scoped changes.

XIII. Extensibility · Beyond chat 15

Work that keeps running without you.

Automations

Save a recurring agent task and trigger it manually, on a schedule (hourly, daily, weekly), or whenever an issue opens. Run locally, or in the cloud so it keeps going with your laptop closed.

Canvases

A shared, interactive surface — a kanban board, a triage board, a markdown plan — that the agent and you both edit. Scaffold one from any session with /create-canvas.

XIV. Built-in agents & commands 16

A few commands worth memorizing.

/security-review

Scans your current changes for high-confidence vulnerabilities with suggested fixes — complements code scanning, Dependabot, and secret scanning. Public preview.

Rubber duck agent

A built-in critic that reviews your plan or diff on a different model, automatically or on request via /rubber-duck.

Voice dictation

Speak your prompts instead of typing them, transcribed locally after a one-time setup.

/chronicle

Summarize recent work across app and CLI sessions — try /chronicle standup or /chronicle cost tips.

XVI. Real-world example 18

Clearing a backlog, in parallel.

A developer starts their morning with twelve open label:bug issues and one hour before standup.

1 · Filter in My work

Search label:bug across all connected repositories and pick the three safest fixes.

2 · Autopilot, three times

Start a session from each issue in Autopilot mode — each gets its own worktree and branch, running concurrently.

3 · Review and open PRs

Switch between sessions in the sidebar, check each diff, and create a pull request straight from the app.

XVII. Real-world example 19

A design pass, without leaving the app.

A frontend developer needs to ship a settings panel that actually looks finished — not just functional.

1 · Plan mode

The agent drafts an approach for the panel; the developer approves it before any code is written.

2 · Build, then /critique

Once the panel renders, /critique flags spacing and hierarchy issues; /typeset and /polish clean them up.

3 · Track it on a canvas

A markdown canvas keeps the checklist, screenshots, and open questions in one editable surface for the team.

XVIII. Real-world example 20

Maintenance that runs unattended.

A small platform team wants issue triage and review nudges to happen whether or not anyone is at their desk.

1 · Daily triage automation

A cloud automation runs each morning, labels new issues, and flags anything that looks urgent.

2 · Agent merge on approved PRs

Once a PR is approved, agent merge fixes remaining blockers in the background and merges the moment CI allows it.

3 · Governed centrally

Admins scope exactly which tools each automation can use, and which plugins the team can install, in managed-settings.json.

XX. Best practices 22

Get more from every credit.

Match model to task

Lighter models for straightforward changes; higher-capability models for debugging and multi-step design work.

Choose mode by stage

Plan to validate scope, Interactive for tight steering, Autopilot once the task is genuinely well-defined.

Scope before you commit

Use Quick chats to clarify requirements first — reduces rework in the full session that follows.

One session, one task

Start a new session when you switch tasks so unrelated history doesn't dilute the agent's context.

Check your usage

Run /chronicle cost tips regularly to catch expensive patterns before they add up.
