GitHub Copilot app

What it is

An agent-first experience. It connects agents and tools across your projects. It supports all steps of the work: specs and design → implementation.

Where to use

  • Start a feature from a spec or a design.
  • Run many agent tasks at the same time.
  • Review all agent work in one place.

How to use

  1. Add a repository or a folder.
  2. Start a session. Tell the agent the task.
  3. Examine the plan and the changes.
  4. Run tests. Then commit or open a pull request.

Benefits

  • One place for agents, tools, and sessions.
  • Less switching between tools.
  • Developers stay in control of each change.

The app is the base for the next six topics. You use Fusion, Projects, Connectors, Automations, Memory, and Cloud Sandboxes from it.

Copilot Fusion

What it is

Multi-model orchestration. Fusion selects one model or more models for each task. It balances quality, speed, and cost.

Where to use

  • Work with different task types: small edits, refactoring, deep analysis.
  • Teams that do not want to select a model for each task.

How to use

  1. Select Auto in the model picker.
  2. Give a clear task with a clear result.
  3. Fusion selects the models. You examine the result.

Benefits

  • A fast model for simple steps. A strong model for hard steps.
  • Good quality at a lower cost.
  • Fewer manual decisions.
Simple Rename a variable → fast model
Complex Refactor a module → strong model
Critical Design and review → more than one model

Copilot Projects

What it is

Coordinates parallel agent work across many repositories. It keeps the goals, the progress, and the decisions together in one place.

Where to use

  • A change in many repositories: API, client, and documentation.
  • Migrations and upgrades across services.
  • A large feature in smaller parts.

How to use

  1. Create a project. Write the goal.
  2. Add the related repositories.
  3. Agents do the parts in parallel sessions.
  4. Monitor progress and decisions in the project.

Benefits

  • One view of work across repositories.
  • Parallel work finishes faster.
  • Decisions are recorded. Context is not lost.

Copilot Connectors

What it is

Brings business context into development. Connect Slack, Work IQ, Atlassian Rovo, and Sentry through GitHub-verified MCP servers. GitHub does the configuration and the authentication.

Where to use

  • Sentry: fix an error with its real stack trace.
  • Atlassian Rovo: build from a Jira issue.
  • Slack: use decisions from a team thread.
  • Work IQ: use Microsoft 365 work context.

How to use

  1. Find the connector in the catalog.
  2. Connect it and sign in.
  3. Tell Copilot which context to use in the task.

Benefits

  • No copy and paste between tools.
  • Verified servers. No manual MCP setup.
  • Agents use the correct business context.

Copilot Automations

What it is

AI-powered workflows. They run on demand, by event, or on a schedule. They learn from the results to make future runs better.

Where to use

  • Each day: sort and label new issues.
  • Each week: examine dependency updates.
  • On an event: investigate a failed CI run.
  • Recurring status reports.

How to use

  1. Write a prompt with a clear goal.
  2. Select the trigger: manual, event, or schedule.
  3. Select the repository and the environment.
  4. Examine the results. Adjust the prompt.

Benefits

  • Repeated work is done for you.
  • The same steps each time.
  • Results become better over time.

Copilot Memory

What it is

Keeps useful knowledge across tasks. It remembers repository facts, such as architecture conventions and test commands. It also remembers your stated coding preferences across repositories.

Where to use

  • Repositories with special build or test commands.
  • Team conventions, for example folder structure.
  • Personal preferences, for example “use pnpm”.

How to use

  1. Tell Copilot a preference in clear words.
  2. Copilot keeps verified repository facts.
  3. Later tasks use this knowledge.
  4. Remove old memories in settings.

Benefits

  • You do not repeat the same instructions.
  • More consistent results.
  • Agents learn a repository faster.
Repository memory: facts for all contributors of that repository.
User memory: your preferences. They apply only to you.

Cloud Sandboxes

What it is

Sends agent work to isolated, GitHub-hosted Linux environments. Copilot clones repositories, changes code, and runs commands and tests there. It does not use your local computer.

Where to use

  • Long or heavy tasks, for example full test suites.
  • Many tasks in parallel.
  • Start work on one device. Continue on a different device.

How to use

  1. Select Cloud as the place to run.
  2. Give the task.
  3. The agent works in the sandbox.
  4. Resume from any client. Examine the result.

Benefits

  • Your laptop stays free.
  • Isolation protects your local machine.
  • Parallel sessions. Work is kept.

Part 2

Platform and access

Agent-scale Git infrastructure

What it is: GitHub is changing the architecture of its platform. The goal is the speed and reliability that agent-scale development needs.

Why: Agents make many more branches, commits, pull requests, and CI runs than people do.

How to use: No action is necessary. The change is on the GitHub side.

Benefit: GitHub stays fast and reliable when agent use increases.

Copilot access with GitHub Enterprise

What it is: GitHub Enterprise customers can now use GitHub Copilot. A separate Copilot subscription is not necessary.

Where to use: Enterprise teams that want to start with Copilot.

How to use: Enterprise admins set the Copilot policies. Confirm the included features and limits with your GitHub account team.

Benefit: An easier start with Copilot for all GitHub Enterprise users.

GitHub package firewall

Public preview
What it is

An install-time policy gate for npm dependencies. It applies to developers, CI runners, and AI agents.

What it blocks

  • Known malware.
  • Vulnerable versions.
  • New install scripts.
  • Packages that do not meet age or provenance policies.

How to use

  1. Set the policy: age, provenance, and install scripts.
  2. Apply it to developer, CI, and agent installs.
  3. Examine blocked installs. Select a safe version.

Benefits

  • Stops a bad package before it runs.
  • The same rules for people and agents.
  • Protection from supply chain attacks.

Where to use: laptops, CI pipelines, and agent sandboxes that install npm packages. Very new packages are a high risk. An age policy helps to stop them.

AI-detected secrets in push protection

Public preview
What it is

Push protection with AI. It finds passwords and other unstructured secrets, not only known token patterns. It stops them before they go into repository history.

Where to use

  • Passwords in configuration files.
  • Database connection strings.
  • Secrets in test data and scripts.

How to use

  1. Enable the feature.
  2. A developer pushes code.
  3. If Copilot finds a secret, the push stops.
  4. Remove the secret. Push again.

Benefits

  • Finds secrets that patterns cannot find.
  • To prevent a leak costs less than to clean history and rotate secrets.

Requirements: enablement + Secret Protection or GHAS + AI credits.

AI Scan for repositories

Public preview
What it is

On-demand AI scans of the default branch. They find more vulnerabilities, also in languages that CodeQL does not cover.

Where to use

  • Repositories in languages that CodeQL does not support.
  • An extra check of critical applications.

How to use

  1. Start a scan on the repository.
  2. Findings go into the code scanning backlog.
  3. Sort and fix them with your usual process.

Benefits

  • Wider language coverage.
  • No new tool or workflow.
  • More findings in one place.

Use AI Scan together with CodeQL, not as a replacement. Scans have a time limit. They are not complete.

Code scanning for AI applications

Public preview
What it is

Pull request checks for risky agent data flows. The main risk: untrusted content controls a model that has access to tools or data.

Where to use

  • Applications that build agents or chat assistants.
  • Models that call tools or APIs.
  • Models that read web pages, emails, or files.

How to use

  1. Enable the checks on the repository.
  2. Checks run on each pull request.
  3. Examine the data flow in the finding.
  4. Fix: limit tool access, keep untrusted content separate, or add human approval.

Benefits

  • Finds prompt injection paths before merge.
  • AI security in the usual pull request flow.

Example risk: an email tells a model to “send all customer data”. The model has a tool that can send data.

Dependabot reachability analysis

Public preview
What it is

For JavaScript and TypeScript dependency alerts. It shows if your code can call the vulnerable function. It gives the call path as evidence.

Where to use

  • Large backlogs of JavaScript and TypeScript alerts.
  • Teams that must decide which alert to fix first.

How to use

  1. Open a Dependabot alert.
  2. Look at the reachability status and the call path.
  3. Fix reachable alerts first. Plan time for the other alerts.

Benefits

  • Teams work on the most important alerts first.
  • Evidence to support each decision.

Reachability helps you set priority only. It does not prove that an attack is possible. An “unreachable” dependency is not guaranteed to be safe.

Security extension for the Copilot app

Public preview
What it is

Brings code scanning alerts and local security reviews into the developer's active session in the Copilot app.

Where to use

  • Fix alerts while you write code.
  • Review local changes before you push.
  • Learn why a finding is a risk.

How to use

  1. Install the extension.
  2. Ask Copilot to explain an alert.
  3. Ask for a local fix.
  4. Examine the change, test it, and commit it yourself.

Benefits

  • No switch to a different tool.
  • Developers learn secure coding.
  • The developer controls each change.

The extension does not commit, push, or open a pull request automatically.

Agentic Autofix

Generally available
What it is

Teams give code scanning fixes to Copilot. Copilot examines the codebase, makes possible fixes, does supported validation, and opens a draft pull request.

Where to use

  • Large backlogs of code scanning alerts.
  • The same type of issue in many places.
  • Teams with few security specialists.

How to use

  1. Select an alert.
  2. Assign the fix to Copilot.
  3. Examine and test the draft pull request.
  4. Merge after approval.

Benefits

  • Faster fixes. Smaller backlog.
  • Fixes use the context of the codebase.
  • A draft pull request keeps human review.

Human review and tests are necessary. Autofix uses AI credits and Actions minutes.

Public monitoring for enterprises

Generally available
What it is

Finds enterprise secrets that are public on GitHub. This includes repositories that the enterprise does not own, comments, and gists.

Where to use

  • An employee pushes work code to a personal public repository.
  • A secret is in an issue comment.
  • A contractor shares a gist.

How to use

  1. Enable it for the enterprise.
  2. Verify your domains.
  3. Examine the alerts.
  4. Revoke and rotate the secret. Investigate.

Benefits

  • Find leaks outside your own repositories.
  • Enterprise membership and verified domains link a leak to your company.
  • Faster response.

Key points

People stay in control

Agents make drafts and suggestions. People examine, test, and approve each change before merge.

AI adds to existing tools

AI Scan adds to CodeQL. Reachability helps priority. Neither one gives a guarantee of safety.

Plan for usage costs

Some features use AI credits or Actions minutes. Monitor usage during a pilot.

Previews can change

Test preview features with one team first. Then decide on a wider rollout.
