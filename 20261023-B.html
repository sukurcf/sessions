G GitHub Copilot OVERVIEW

AI assistance for the work around your code.

GitHub Copilot can suggest code, explain a codebase, help plan a change, and work on tasks you assign it.

It uses the context available in the feature you choose. You still decide what to ask, what to accept, and what to ship.

  • 1WriteGet inline code suggestions while you edit.
  • 2UnderstandAsk questions about code, issues, and pull requests.
  • 3ChangeAsk an agent to edit files and work through a task.
  • 4ReviewInspect the result and test it before you rely on it.

G GitHub Copilot REQUEST TO RESPONSE

A request passes through checks, a service, and a model.

A simplified mental model. The exact path and controls depend on the feature and client.

Your requestPrompt plus relevant code and conversation context
Pre-model checksAccess, policy, context selection, and input content filters
Copilot service / proxyOrchestrates the request and routes to an available model
LLM providerGenerates a completion or response from the request
Post-model checksOutput content filters and public-code matching, where enabled
Then you decideReview the suggestion or change. Accept it, edit it, or reject it.
G GitHub Copilot MODELS & CHECKS

Models can differ. Filters add checks.

Copilot supports models from several providers. The available choices depend on your plan, surface, and organization settings.

Providers include OpenAIAnthropicGoogleMicrosoftMoonshot AIxAI

Content filters: default Copilot models check prompts and responses for harmful, offensive, or off-topic content.

Public-code matching: when enabled, an inline suggestion can be checked against public GitHub code. Policy can block a match or show its source. This does not prove all output is unique.

Model lists and access can change. Check the current model list and your Copilot feature settings.

Copilot uses the context available to your IDE to predict code that may fit next.

  • 3ChooseAccept, keep typing, or dismiss the suggestion.

G GitHub Copilot ASK

Ask mode helps you understand code.

Use it to explain a function, explore a codebase, or compare two approaches.

  • 1Set the contextOpen or select the code you want Copilot to inspect.
  • 2Ask a focused questionName the file, function, or behavior.
  • 3Check the answerConfirm the explanation against the code.
EXAMPLE QUESTION
Explain what happens when
the cart is empty.

Point me to the code and tests.
Do not edit files.

Ask mode is for answers and explanations. Use Plan or Agent when you want help with a larger change.

G GitHub Copilot PLAN

Plan mode turns a broad goal into steps.

Use it when a task touches several files or when you need to check the approach first.

  • 1Describe the goalState the expected result and any limits.
  • 2Review the planCheck files, steps, and open questions.
  • 3Adjust the scopeCorrect the plan before implementation.
EXAMPLE REQUEST

“Plan server-side validation for signup. Find the route, current tests, and any project rules. Show the steps first.”

A useful plan shows

files to inspect steps to take tests to run

A plan is a proposal. Review it and confirm the scope before work continues.

Plan mode and its controls vary by client. Use it to reduce uncertainty before you delegate the work.

G GitHub Copilot AGENT

Agent mode carries out a multi-step task.

Give the agent a clear goal. It can inspect files, make changes, use available tools, and check its work.

  • 1InspectFind relevant files and project conventions.
  • 2ChangeEdit code and tests within the task scope.
  • 3CheckRun tools that are available and permitted.
  • 4ReviewInspect the diff and test results yourself.
EXAMPLE REQUEST

“Add server-side validation to signup. Follow existing patterns, add focused tests, run the relevant test, and report what changed.”

Agent tools and permissions depend on the client and organization settings. Review all changes before you merge them.

G GitHub Copilot REPEATABLE TASKS

Save prompts you want to reuse on demand.

.github/prompts/review-tests.prompt.md
# Review test coverage

For the changed code:
- Find the related tests.
- Identify missing cases.
- Suggest focused tests.
- Do not change files until asked.

A prompt file is a reusable task template. Select or reference it when that task comes up.

  • 01Write one prompt for one repeatable job.
  • 02Keep it in the repo so the team can find it.
  • 03Invoke it when useful; it is not always-on guidance.

Repository prompt files commonly use .github/prompts/*.prompt.md. Support and invocation differ by IDE.

G GitHub Copilot SPECIALIST ROLE

Make a specialist you can call again.

.github/agents/test-writer.agent.md
---
name: test-writer
description: Add focused tests for a code change.
tools: ["read", "edit", "search"]
---

Follow the repository's test patterns.
Cover expected behavior and edge cases.
Run the focused test command.
Report files changed and test results.
  • Role: name the specialist's job and when to use it.
  • Instructions: write the approach in the Markdown body.
  • Tools: allow only what that job needs; available tools vary.
  • Use: select it for a task, or let a supported agent delegate to it.

Keep the names straight: AGENTS.md gives agents instructions. A .agent.md file defines a reusable custom agent profile.

Custom-agent paths, fields, and support depend on the Copilot surface. Check the configuration guide for your environment.
