II. Overview 04

What is MCP.

An open protocol — introduced by Anthropic in late 2024 — that standardizes how applications feed context to large language models. If REST is how apps talk to servers, MCP is how AI apps talk to tools and data.

Open standard

Vendor-neutral and open-source, built on JSON-RPC 2.0. Any model, any language, any app.

"USB-C for AI"

One universal port. Plug a model into files, APIs, and databases without custom glue code.

Client–server

Apps run clients that connect to servers exposing capabilities over stdio or HTTP.

III. The problem it solves 05

The M×N problem.

Before MCP, every AI app needed a bespoke connector for every tool. M apps × N tools meant M×N integrations to build, test, and maintain — a combinatorial mess.

Before MCP

M × N

Every app re-implements a connector for every source. Duplicated effort, brittle, doesn't scale.

With MCP

M + N

Build a server once — any client uses it. Build a client once — it works with every server.

Interoperable

Swap models or apps freely — the integration layer stays put.

Reusable

Write an integration once; the whole ecosystem benefits.

Breaks silos

Give models secure, structured access to data behind your walls.

V. Primitives 07

The building blocks.

MCP is deliberately small. Servers expose three primitives; clients offer three back. Each has a natural "controller" — who decides when it's used.

SERVER → CLIENT · EXPOSED TO THE MODEL

Tools

Executable actions the model can call. Model-controlled.

Resources

Read-only data loaded for context. App-controlled.

Prompts

Reusable templates & workflows. User-controlled.

CLIENT → SERVER · OFFERED BACK

Sampling

Server asks the client's LLM to generate a completion.

Elicitation

Server requests extra input from the user mid-task.

Roots

Client shares which files/URIs the server may access.

V. Primitives · deep dive 08

Tools, resources & prompts.

The three server primitives map to a simple idea: who decides when each is used.

Tools model-controlled

Functions the model invokes to act or fetch live data — create an issue, run a query, send an email. Inputs are described with a JSON schema.

create_issue(title, body)

Resources app-controlled

Read-only data the app loads into context — files, DB rows, API responses. Addressed by URI. Like a GET: no side effects, just information.

file:///README.md

Prompts user-controlled

Parameterized templates and workflows a user triggers — often surfaced as slash commands. Package best-practice instructions for reuse.

/summarize-pr 1423

Client primitives — sampling, elicitation & roots — let servers ask the client for completions, input, or file access.

VI. Hands-on · Python SDK 09

Build a server · Python.

The official Python SDK ships FastMCP — decorate functions and you have a working server exposing all three primitives.

# server.py — a minimal MCP server
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("Demo")

@mcp.tool()
def add(a: int, b: int) -> int:
    return a + b

@mcp.resource("greeting://{name}")
def greet(name: str) -> str:
    return f"Hello, {name}!"

@mcp.prompt()
def review(code: str) -> str:
    return f"Review this:\n\n{code}"

if __name__ == "__main__":
    mcp.run()

Run & inspect

mcp dev server.py opens the MCP Inspector to call your tools live.

Connect it

mcp install server.py for Claude Desktop, or add it to VS Code's .vscode/mcp.json.

pip install "mcp[cli]" · github.com/modelcontextprotocol/python-sdk

VI. Hands-on · Run & deploy 10

Run it · local or remote.

The same server can run right beside your editor or as a shared service on the network — only the transport changes.

Local · stdio

On your machine

▸Client launches the server as a subprocess
▸Talks over stdin/stdout — no ports, no network
▸Secrets & files stay on your device
▸Ideal for filesystem, git & personal dev tools
// .vscode/mcp.json
"files": {
  "command": "python",
  "args": ["server.py"]
}

Remote · HTTP

Anywhere on the network

▸Reached by URL over Streamable HTTP
▸Shared by many users & teams at once
▸Secured with OAuth 2.1 / bearer tokens
▸Deploy to containers, serverless or PaaS
// .vscode/mcp.json
"github": {
  "url": "https://mcp.example.com/mcp"
}

Transport negotiated at initialize · stdio for local · Streamable HTTP for remote (supersedes the older HTTP+SSE transport)
