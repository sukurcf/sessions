G GitHub Copilot REPOSITORY INSTRUCTIONS

Repository instructions

Use this file for project conventions that should guide Copilot across tasks.

.github/copilot-instructions.md
# Project conventions
Use the shared validation helpers.
Follow existing naming patterns.
Add focused tests for behavior changes.
  • Write stable rulesInclude conventions that apply to many tasks.
  • Keep rules actionableSay what to do, not only what to avoid.
  • Avoid duplicationPut local rules in a file with a narrower scope.
iInstructions guide the work. They do not grant access to files or tools.

Check that your Copilot client supports this file and loads it for the repository.

G GitHub Copilot DIRECTORY GUIDANCE

AGENTS.md

Use AGENTS.md to keep guidance beside the code it describes.

repo/ ├── AGENTS.md # repository guidance └── src/ ├── AGENTS.md # source guidance └── api/ └── AGENTS.md # API guidance
  • Root fileSets guidance for the repository when the client supports it.
  • Nested fileAdds rules for its directory and relevant descendants.
  • MarkdownWrite short rules and commands. Basic use needs no frontmatter.

Discovery and rule combination depend on the Copilot client.

G GitHub Copilot FILE-PATTERN RULES

Path-specific instructions

Use applyTo to attach rules to matching file paths.

.github/instructions/components.instructions.md
---
applyTo: "src/components/**"
---
# Component rules
Use shared design tokens.
Keep keyboard navigation working.
Update component tests.
  • MatchThe glob selects the paths that receive these rules.
  • SeparateUse a different file for each distinct area.
  • VerifyCheck that a matching file receives the guidance.
iUse a glob that matches the paths in your repository. Pattern support can vary by client.
G GitHub Copilot PROMPT FILES

Prompt files

Save a task you want to start on demand.

.github/prompts/explain-test.prompt.md
# Explain a failing test
Read the test and its error output.
Identify the likely cause.
Suggest a next step.
Do not edit files.
  1. AWriteDescribe one clear task in a .prompt.md file.
  2. BRunSelect it from a prompt picker or command supported by your client.
  3. CCheckReview the result against the request and source files.

File locations and launch methods depend on the Copilot client.

G GitHub Copilot SKILLS

Agent skills

A skill gives a supported agent a reusable procedure and any needed reference files.

skill discoverySKILL.md

SKILL USE

Task arrives→Find relevant skill
Skill loads→Read procedure
Work starts→Follow its steps
  • DescriptionHelps a supported agent decide when a skill applies.
  • ProcedureSKILL.md contains the steps to follow.
  • ReferencesOptional files hold details needed for specific tasks.
iA skill is a procedure, not a saved user request. Use it when the method needs to be reused.
G GitHub Copilot SKILL FILES

Skill files

Put SKILL.md in a named folder. Add supporting files only when the procedure needs them.

.github/skills/dependency-update/ ├── SKILL.md ├── references/ │ └── upgrade-policy.md └── scripts/ └── check-lockfile.sh
SKILL.md
---
name: dependency-update
description: Prepare dependency updates
---
# Update procedure
Read the package and upgrade policy.
Check the release notes for breaking changes.
Run the project checks.

Use a folder location and metadata supported by your Copilot client. Review scripts before use.

G GitHub Copilot AGENT ROLES

Custom agents

Create a named agent for work that needs a consistent role and clear boundaries.

  • RoleGive the agent one clear purpose.
  • BoundariesState what it should and should not do.
  • SelectionChoose it in a client that supports custom agents.

When to use one

Use a custom agent when a task needs its own role, settings, or tool access. Use a skill when you only need reusable steps.

Agent selection and settings depend on the Copilot client.

G GitHub Copilot AGENT FILE

Agent files

An agent file combines its identity with instructions for its role.

.github/agents/docs-editor.agent.md
---
name: docs-editor
description: Improves project documentation
---
# Mission
Make project documentation clear and concise.
# Rules
- Keep the technical meaning.
- Do not change source code.
- List the files you changed.
  • FrontmatterSet the name and description. Add only supported fields.
  • InstructionsState the mission, boundaries, and expected result.
  • Tool accessLimit the agent to tools needed for its role.

File location, metadata, and tool settings vary by client.

G GitHub Copilot AGENT WORKFLOW

Create and test an agent

Start with a narrow role, then verify the result in your Copilot client.

Example role test-author ├── Inspect nearby tests ├── Add focused coverage ├── Run the relevant command └── Report the result
  1. ADefineWrite the role and its boundaries.
  2. BLimitEnable only the tools it needs.
  3. CDiscoverConfirm the client can select the agent.
  4. DTestCheck its work and refine the instructions.
iReview the agent's output. Its configuration does not guarantee correct results.
G GitHub Copilot MCP SERVERS

MCP servers

An MCP server exposes capabilities to a compatible client through Model Context Protocol.

ClientCopilot clientConnects to a configured server.
→
ProtocolMCP serverAdvertises supported capabilities.
→
ServiceExternal systemProvides data or performs an action.

ConnectThe client starts or contacts the configured server.

DiscoverThe server reports the capabilities it offers.

RequestThe client calls a capability and receives its result.

A server can offer tools, resources, or prompts. The client controls which capabilities are available.

G GitHub Copilot MCP TOOLS

MCP tools

A tool is a named action that an MCP server makes available to a client.

Example tool descriptions
search_docs
Input: query · returns matching documents

update_record
Input: id, fields · changes a record
  • InputsThe schema defines which arguments the tool accepts.
  • ResultsThe server returns data or a status to the client.
  • EffectsCheck whether the tool reads data or changes it.

Make only task-relevant tools available. Review write actions before use.

G GitHub Copilot TOOLSETS

Toolsets

Some clients group MCP tools into sets that can be enabled for a task.

GroupKeep related tools together.

SelectEnable the tools needed for the task.

LimitLeave unrelated or write-capable tools out.

Client feature

Toolsets are a client feature. They are not a separate server or a core MCP protocol capability.

Toolset names and behavior depend on the Copilot client.
