G GitHub Copilot INSTRUCTIONS

Instructions: file types and scope

Use instruction files for rules that should guide Copilot across tasks. The file type and location determine where guidance applies.

.github/instructions/api.instructions.md
---
applyTo: "src/api/**"
---
- Follow the existing response helpers.
- Add or update focused API tests.
  • AGENTS.mdMarkdown guidance in a directory. Nested files can add rules for their own area.
  • .github/copilot-instructions.mdRepository-wide Copilot guidance in clients that support this file.
  • Path-specific instructionsUse .instructions.md with an applyTo glob to target matching files.

File names, discovery rules, and support can vary by Copilot client and version. Check your client documentation.

G GitHub Copilot CUSTOM INSTRUCTIONS

Custom instructions: what they are and how they work

Custom instructions are persistent guidance for Copilot. A supported client includes relevant rules with a task.

.github/copilot-instructions.md
# Project conventions
Use existing validation helpers.
Follow the current folder structure.
Add focused tests for behavior changes.
Run the relevant test command.
  • Use forStable project conventions, coding style, and test expectations.
  • Keep them conciseSpecific rules are easier for Copilot to apply correctly.
  • Check client supportSupported instruction files differ between clients and versions.
iInstructions guide a task. They do not replace the task request or grant access to files and tools.
G GitHub Copilot AGENTS.MD

AGENTS.md: what it is and how it works

AGENTS.md is a Markdown file for agent guidance in a repository or directory tree.

repo/ ├── AGENTS.md # repository guidance └── src/ ├── AGENTS.md # source guidance └── api/ └── AGENTS.md # API guidance
  • Root fileProvides guidance from the repository root when the client supports it.
  • Nested fileAdds local guidance for its directory and relevant descendants.
  • Plain MarkdownWrite short rules, patterns, and commands. No special frontmatter is required for the basic format.

Clients differ in how they discover and combine AGENTS.md files. Check the relevant Copilot documentation.

G GitHub Copilot PATH-SPECIFIC INSTRUCTIONS

Path-specific instructions: what they are and how they work

Use an .instructions.md file and an applyTo glob for rules that apply to matching files.

.github/instructions/api.instructions.md
---
applyTo: "src/api/**"
---
# API rules
Use the shared response helpers.
Add tests for validation changes.
  • MatchThe glob identifies which file paths receive the guidance.
  • SeparateUse separate files for different parts of the codebase.
  • VerifyOpen a matching file and confirm that your client applies the instruction.
iPath patterns and support vary by client. Keep the example pattern aligned with the files in your repository.
G GitHub Copilot CUSTOM PROMPT FILES

Custom prompt files: what they are and how they work

A prompt file stores a reusable task that a developer starts when they need it.

.github/prompts/review-api.prompt.md
# Review API changes
Review the changed API files.
Check validation and error handling.
Return findings with file and line.
Do not edit files.
  1. ACreateSave a .prompt.md file in a supported prompt folder.
  2. BStartChoose the prompt from the supported command or prompt picker.
  3. CReviewCheck the response against the task and source files.

Prompt file discovery and invocation depend on the Copilot client.

G GitHub Copilot AGENT SKILL FILES

Agent skills: file structure and creation

Put a SKILL.md file in a named skill folder. Add references or scripts only when they support the procedure.

SKILL.md
---

description: Review API changes
---

Read the changed route and its tests.
Check the API conventions.
Report findings with file and line.

Use the skill folder location and metadata supported by your Copilot client. Review any script before you include or run it.

G GitHub Copilot CUSTOM AGENTS

Custom agents: what they are and how they work

A custom agent is a named assistant profile with a focused purpose and its own instructions.

  • IdentityA name and description help people choose the right agent.
  • InstructionsThe Markdown body defines its role and limits.
  • UseSelect it in a supported client, then give it a task.

Optional configuration

Supported clients can set a model or limit the tools available to an agent.

Agent selection, metadata, and tool controls depend on the Copilot client.

G GitHub Copilot CUSTOM AGENT FILES

Custom agent files: structure

A custom agent file combines YAML frontmatter with a Markdown instruction body.

.github/agents/test-author.agent.md
---
name: test-author
description: Writes focused tests
---
# Mission
Add focused tests for the requested change.
# Rules
- Inspect nearby tests; follow patterns.
- Do not change production code.
- Report the test command and result.
  • FrontmatterUse the required identity fields. Add optional metadata only when your client supports it.
  • Instruction bodyWrite a clear mission, steps, boundaries, and handoff format.
  • Tools and modelUse client-supported settings to limit access to what the role needs.

File name, folder, metadata fields, and accepted tool names vary by client.

G GitHub Copilot CUSTOM AGENT FILES

Custom agent files: creation and testing

Build one focused role, check that your client discovers it, then test it on a real task.

EXAMPLE ROLE

Test author: inspect existing tests, add focused coverage, run the relevant command, and report the result.

  1. WriteDescribe the role, task boundaries, and expected output.
  2. LimitEnable only the tools and permissions that the role needs.
  3. DiscoverConfirm the client lists or accepts the new agent.
  4. TestCheck its actions, results, and handoff; refine the file.
iKeep user review in the workflow. A custom agent is configuration, not proof that its output is correct.
G GitHub Copilot MCP SERVERS

MCP servers: what they are and how they work

An MCP server is a program or service that exposes capabilities to a compatible client through Model Context Protocol.

ClientCopilot clientConnects to a configured server.
→
ProtocolMCP serverAdvertises supported capabilities.
→
ServiceExternal systemProvides data or performs an action.

ConnectThe client starts or contacts the configured server.

DiscoverThe server reports the capabilities it offers.

RequestThe client calls a capability and receives its result.

A server may expose tools, resources, or prompts. The client determines which capabilities are available to the agent.

G GitHub Copilot MCP TOOLS

MCP tools: what they are and how they work

An MCP tool is a named action that a server makes available to a connected client.

Example tool descriptions
search_issues
Input: query · reads matching issues

create_issue
Input: title, body · creates an issue
  • DefinitionA name, description, and input schema.
  • Call and resultThe client sends arguments to the server and receives the result.
  • Side effectsCheck write actions, arguments, and approval settings.

Enable only tools that fit the task and your access policy.

G GitHub Copilot MCP TOOLSETS

MCP toolsets: what they are and how they work

Some Copilot clients use toolsets to group or select the tools an agent can use.

GroupPut related tools together, such as search and read actions for an issue tracker.

SelectMake a supported toolset available to a session, agent, or task.

LimitKeep unrelated or write-capable tools out of the available set.

Important distinction

Toolsets are a client-level grouping or selection feature. They are not a separate MCP server or a core MCP protocol capability.

Toolset names, behavior, and configuration depend on the Copilot client.
