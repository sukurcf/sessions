GitHub Copilot 01 / PROMPTING & CONTEXT

Give Copilot a brief it can execute

A strong prompt joins a clear outcome with the smallest set of useful project context.

Worked example · feature requestGOAL → CHECKS
Goal: Expire password-reset links after 30 minutes.

Context: Read the reset handler and its existing tests.

Constraints: Keep the token format. Use the shared clock helper.

Acceptance: Expired links are rejected; tests cover both sides
             of the 30-minute boundary.
OutcomeSay what should change, and why.
ContextPoint to relevant files, issues, or examples.
ConstraintsState compatibility, scope, and boundaries.
AcceptanceDefine observable checks and expected results.
Engineer the context, not just the prompt

Attach relevant files. Keep conversation history focused. Add durable repository guidance for rules that apply across tasks.

Make complex work easier to verify

Put key requirements first, include examples or tests, split large tasks, then review and iterate on the output.

GitHub Copilot 02 / PLAN & AGENT MODES

Plan first when alignment matters

Plan mode prepares the work. Agent mode carries it out. Choose based on uncertainty, scope, and risk.

Plan mode

Read · reason · outline

Researches the task and drafts steps before code changes begin.

  • Uses read-only tools to inspect the codebase and identify constraints.
  • Breaks work into actions and calls out open questions.
  • You refine and approve the plan before implementation.

Agent mode

Explore · edit · verify

Takes a task, chooses files and tools, then works through the changes.

  • Edits across the project and runs commands when needed.
  • Can iterate on test or command results; you can steer while it works.
  • You review the diff and approve proposed commands as configured.
Rule of thumb: If scope or acceptance is still uncertain, plan first. If the task is clear and you are ready to act, use Agent mode. Plan mode availability depends on the Copilot client.

GitHub Copilot 04 / COPILOT CODING AGENT

Delegate work beyond your editor

Copilot coding agent—called Copilot cloud agent in current GitHub Docs—works in a separate cloud environment.

Interactive · local IDE

Agent mode

  • Works in your editor and local project context.
  • Streams edits and offers terminal commands while you steer.
  • Useful when you want to stay close to implementation.
Delegated · GitHub cloud

Coding agent

StartAssign an issue or send a task prompt.
WorkResearches, edits, and runs checks in an ephemeral environment.
InspectReview the branch, diff, and session log.
IterateGive feedback; open or refine a pull request.

Two start paths: assigning an issue creates a pull request. Starting from a prompt works on a branch by default, so you can inspect and iterate before opening one.

GitHub Copilot 05 / COPILOT CLI

Bring the agent to your terminal

Use the CLI to explore a repository, make a change, or ask a GitHub question without leaving the command line.

Interactive session

Start a conversation in the current project. Switch between ask/execute and plan modes as the task needs.

$ copilot
# Shift+Tab cycles modes

Ask: explain code, find context, compare options.

Plan: clarify scope before writing code.

Execute: edit files and run relevant commands.

Steer: give feedback while work continues.

Programmatic prompt

Pass one prompt with -p for a task that should finish and exit.

$ copilot -p "Summarize this week's commits" --allow-tool='shell(git)'
Permission is part of the prompt design

Read/search is generally allowed by policy; edits and commands may need approval. Restrict available tools and use narrow allow/deny rules. Deny rules take precedence.

Good default: Keep permissions limited to the work. Avoid broad auto-approval unless you understand the access it grants.

GitHub Copilot 06 / COPILOT CODE REVIEW

Use review to find issues in the diff

Copilot can review a pull request, leave comments, and suggest changes. Treat the feedback as a review signal—not as proof that code is safe or correct.

01Open a pull requestGive reviewers the change and its intent.
02Request CopilotAsk for a review on the pull request.
03Inspect commentsCheck evidence and suggested edits.
04Fix and verifyApply useful changes; run relevant tests.
05Review againRequest another review after new changes, if needed.

Improve signalAdd repository or path-specific review instructions for team conventions.

Know the defaultCopilot leaves a comment review by default—not an approval or request for changes.

Keep the human gateRead the diff, validate findings, and use your normal test and approval process.
