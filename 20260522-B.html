What is Copilot · Nº 01

An AI-powered coding assistant built into your editor.

GitHub Copilot is an AI coding assistant that helps you write code faster and with less effort. It works directly inside your IDE, on GitHub.com, GitHub Mobile, Windows Terminal, and in the CLI.

  • Real-time inline code suggestions as you type — from single lines to entire functions
  • Natural-language chat for explaining, refactoring, debugging, and generating code
  • Agentic capabilities — autonomous planning, multi-file edits, terminal commands, and self-correction
  • Copilot Spaces — organize code, docs, and specs into shared context for more relevant answers
  • Six plans: Free, Student, Pro, Pro+, Business, and Enterprise

Installation · Nº 02

Install once, use everywhere.

Copilot runs wherever you code. Install the extension for your editor, sign in with your GitHub account, and start coding. No separate server or API key required.

  • VS Code — hover the Copilot icon in the Status Bar → "Set up Copilot", or install from the Extension Marketplace
  • JetBrains IDEs — install the Copilot plugin from Marketplace (IntelliJ, PyCharm, WebStorm, etc.)
  • Visual Studio — built into VS 2022 v17.10+, or install as extension
  • Xcode — GitHub Copilot for Xcode extension
  • Eclipse — GitHub Copilot plugin for Eclipse IDE
  • Neovim / Vim — github/copilot.vim plugin
  • CLI — gh extension install github/gh-copilot
  • GitHub.com & Mobile — Copilot Chat built in, plus GitHub Mobile for iOS and Android
  • Windows Terminal Canary — Terminal Chat interface

Inline Suggestions · Nº 03

Ghost text that completes your thought.

As you type, Copilot shows dimmed "ghost text" completions inline — from single expressions to entire functions. The model reads your current file, open tabs, imports, and surrounding comments to tailor every suggestion.

  • Tab to accept the full suggestion; Esc to dismiss
  • ⌘→ (Mac) or Ctrl+→ (Win/Linux) to accept word-by-word
  • Hover over the suggestion to browse alternative completions
  • Write a comment describing what you need — Copilot generates the implementation
  • Enable or disable per language via the Copilot Status Bar menu or github.copilot.enable setting
  • Snooze completions temporarily via the Status Bar menu (increments by 5 minutes)

Next Edit Suggestions · Nº 04

Copilot predicts where you'll edit next.

Next Edit Suggestions (NES) go beyond completing the current line. Based on the edits you're making, NES predicts both the location of your next edit and what that edit should be. An arrow in the editor gutter points to the next suggested change.

  • Press Tab to jump to the suggestion, then Tab again to accept the edit
  • Catches typos and logic mistakes — e.g., fixing conts → const or inverted ternary expressions
  • Tracks intent changes — rename Point to Point3D and NES suggests adding a z property
  • Refactoring helper — rename a variable once, NES suggests updates everywhere else
  • Enable via github.copilot.nextEditSuggestions.enabled in VS Code settings
  • Available in VS Code, Xcode, and Eclipse

Copilot Chat · Nº 05

A conversational interface for your codebase.

Copilot Chat is a chat-based interface inside your editor. Ask it to explain code, fix bugs, write tests, generate documentation, or run autonomous multi-file tasks. It understands your workspace context and can reference specific files and symbols.

  • Chat view — persistent sidebar conversation (⌃⌘I on Mac / Ctrl+Alt+I on Win/Linux)
  • Inline chat — quick prompt right in the editor (⌘I / Ctrl+I)
  • Attach context with the Add Context button — files, symbols, selections, web URLs, MCP resources
  • Use / to invoke prompt files and agent skills as slash commands
  • Available in VS Code, JetBrains, Visual Studio, Eclipse, Xcode, GitHub.com, and GitHub Mobile
  • Choose your model — GPT-4o, Claude Sonnet 4, GPT-5, and more via the model picker

Chat Modes · Nº 06

Three built-in agents, one conversation.

VS Code ships three built-in agents, each optimized for a different level of autonomy. Select the agent from the dropdown at the top of the Chat view. You can switch between them at any time during a session.

  • Ask — read-only Q&A. Uses agentic capabilities to research your codebase and answer questions about code, concepts, or VS Code itself. Never modifies files. Best for learning and exploring.
  • Agent — the most powerful. Works autonomously: plans the approach, creates and edits files across your project, runs terminal commands, invokes tools, reads output, and self-corrects. Use for complex, multi-file tasks. Supports three permission levels: Default Approvals, Bypass Approvals, and Autopilot (Preview).
  • Plan — creates a structured, step-by-step implementation plan before writing any code. Analyzes your codebase, asks clarifying questions, and produces a detailed plan. When the plan looks right, hand it off to an implementation agent to execute.
  • Note: Edit mode is deprecated. Use Agent mode for multi-file code edits instead.

Custom Agents · Nº 07

Define your own agents for specialized workflows.

Beyond the three built-in agents, you can create custom agents — each with its own persona, tool restrictions, model preferences, and handoffs. Custom agents are .agent.md Markdown files stored in your workspace or user profile.

  • Workspace agents: .github/agents/ directory. User agents: ~/.copilot/agents/
  • YAML frontmatter defines description, tools, model, handoffs, and agents (subagents)
  • Example: a "Planner" agent restricted to read-only tools with a handoff button to an implementation agent
  • Example: a "Security Reviewer" agent that only reads code and flags vulnerabilities
  • Handoffs — define sequential workflows: Planning → Implementation → Code Review
  • Reusable across local agents, Copilot CLI background agents, and cloud agents
  • Use Chat: Open Customizations command or the Agent Customizations editor to create and manage

Prompt Files · Nº 08

Reusable slash commands for your team.

Prompt files (.prompt.md) are Markdown-based reusable prompts that you can commit to your repository. They simplify common tasks — like scaffolding a component, running tests, or preparing a PR — so everyone invokes the same high-quality prompt with a / slash command.

  • Store in .github/prompts/ (workspace) or user profile for cross-workspace access
  • YAML frontmatter: description, agent, model, tools — specify which agent and tools to use
  • Invoke with /prompt-name in the Chat view — they appear alongside agent skills as slash commands
  • Reference workspace files with Markdown links for automatic context inclusion
  • Generate with AI: type /create-prompt in chat and describe the task you want to automate
  • Extract from conversation: after a multi-turn session, ask "turn this into a reusable prompt"
  • Share across the team via version control — prompts evolve with the codebase

Custom & Path Instructions · Nº 09

Shape every response with layered instructions.

Copilot supports multiple layers of custom instructions that stack to tailor its output. From global preferences to file-level rules, each layer narrows context so suggestions match your conventions.

  • Project instructions — .github/copilot-instructions.md in your repo root. Automatically included in every chat request. Define coding standards, preferred libraries, architectural patterns.
  • AGENTS.md — always-on instructions compatible with multiple AI agents. Place in workspace root or subfolders for scoped rules.
  • Path-specific instructions — .instructions.md files with an applyTo glob pattern in the frontmatter. Example: applyTo: "**/*.test.ts" applies test-specific conventions only when working on test files.
  • Personal instructions — stored at ~/.copilot/instructions/. Apply across all your workspaces.
  • Organization-level — shared across teams via GitHub organization settings.
  • Generate with AI: /init for workspace-wide, /create-instruction for targeted rules. Type /instructions to manage.

MCP · Nº 10

Model Context Protocol — connect Copilot to anything.

MCP (Model Context Protocol) is an open standard for connecting AI models to external tools and services. MCP servers provide tools that Copilot can invoke during Agent mode, plus resources, prompts, and interactive MCP Apps — giving it access to databases, cloud services, and internal APIs.

  • Install from the VS Code Extensions view: search @mcp to browse the MCP server gallery
  • Configure manually in .vscode/mcp.json (workspace, shareable via source control) or user profile
  • Supports stdio (local) and http (remote) server types
  • Beyond tools: servers can provide resources (read-only context), prompts (template commands), and MCP Apps (interactive UI in chat)
  • Sandbox mode (macOS/Linux) — restrict file system and network access for security
  • Works in Dev Containers via devcontainer.json configuration
  • Auto-discovery: reuse MCP server configs from other tools like Claude Desktop

Custom Agents · Nº 11

Build specialized agents with .agent.md.

Custom agents let you define persistent AI personas with specific roles, tool access, and model preferences. Each agent is a Markdown file (.agent.md) with YAML frontmatter and instructions. They appear in the agent dropdown in the Chat view, alongside the built-in Agent, Plan, and Ask.

  • Store in .github/agents/ (workspace, shareable) or ~/.copilot/agents/ (personal)
  • Frontmatter fields: description, tools, model, agents (subagents), handoffs
  • Tool restrictions — a "Planner" agent can be limited to read-only tools like search/codebase and web/fetch
  • Handoffs — create sequential workflows with handoff buttons: Plan → Implement → Review
  • Subagents — orchestrate multi-agent workflows where a coordinator delegates to specialists
  • Also compatible with Claude format: .claude/agents/ directory
  • Create with Chat: New Custom Agent command or the Agent Customizations editor

Agent Skills · Nº 12

Agent Skills — portable capabilities across agents.

Agent Skills are folders of instructions, scripts, and resources that Copilot loads when relevant. Built on an open standard (agentskills.io), skills work across VS Code, GitHub Copilot CLI, and Copilot cloud agent — making them truly portable.

  • Each skill is a directory with a SKILL.md file defining name, description, and instructions
  • Store in .github/skills/ (workspace) or ~/.copilot/skills/ (personal)
  • Can include scripts, examples, templates, and other resources alongside instructions
  • Loaded on-demand — Copilot automatically loads relevant skills based on your task
  • Available as slash commands: type /skill-name in chat to invoke manually
  • Generate with AI: type /create-skill or extract from a conversation
  • Unlike custom instructions (VS Code-specific, always-on), skills are task-specific and cross-platform

Debug Logs · Nº 13

The Agent Debug Logs panel.

When agents run multi-step operations, the Agent Debug Log panel (Preview) gives you full visibility into what's happening under the hood. It shows a chronological event log of tool call sequences, LLM requests, token usage, prompt file discovery, and errors — invaluable for debugging unexpected behavior.

  • Open via the Chat view ⋯ menu → "Show Agent Debug Logs"
  • Shows timestamped events: tool calls, file operations, terminal commands, model requests and responses
  • See token usage per request and which prompt files / instructions were loaded
  • Attach a snapshot of debug events to a chat conversation for AI-assisted troubleshooting
  • /troubleshoot command — ask the AI to analyze debug logs. E.g., /troubleshoot how many tokens did I use?
  • Chat Debug view — shows raw LLM request/response details including full system prompt and tool payloads
  • Enable verbose logging: set github.copilot.chat.agentDebugLog.enabled to true
